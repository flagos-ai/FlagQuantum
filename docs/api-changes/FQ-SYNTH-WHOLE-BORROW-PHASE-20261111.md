# Whole-register borrowed phase consistency

The user authorized native numeric-view completion and independent acceptance
of all 216 frozen programs. Fresh acceptance exposed historical zero-workspace
failures in whole-register mutable helpers. The preceding implementation also
fails these tests. A separate phase expression route for whole-register helpers
materializes numerical scratch where the sliced helper already emits exact
bounded phase effects. The isolated generic repair passes all 36 amplitude
amplification tests; this exploratory result is not production acceptance.

## Contract

Whole-register mutable helper capture may retain an internal borrowed-unitary
context marker. Within that context, phase expressions and controlled phases
use the existing exact polynomial/factored phase capture, under its unchanged
source, predicate, factor and operation bounds. Root capture outside a helper
keeps its existing path. Whole and partial borrows must agree in absolute
complex amplitudes for equivalent bindings. Aliases retain their declared
numeric formats and logical order.

The context marker is internal Compiler state, not a new public concept or IR
attribute. It neither denotes expanded callbacks nor authorizes new effect or
ownership operations. Closed helper templates still require independent
unitarity verification. Const, initialization, alias, Output escape and
incomplete-search checks remain. Signed/fixed-point comparisons retain the
established checked numeric route; a representation change must not bypass
unsupported-format refusal or introduce an accidental new phase grammar.

No workspace or operation ceilings increase. No original coefficients,
iterations or source identities change. No exactness, resource optimality or
all-program certification is inferred from reduced scratch.
