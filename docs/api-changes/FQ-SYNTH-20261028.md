## User journey and value

A user describes unsigned arithmetic in composable Python quantum functions,
or imports an original Qmod file. Synthesis owns widths, physical register
allocation, reversible arithmetic, carry handling, and intermediate cleanup.
The user still chooses the input state, input widths, mathematical function,
and result interpretation. Existing Circuit users can embed their blocks or
compose the generated IR into a larger Circuit using an explicit qubit map.

This connects FlagQuantum's arithmetic and compilation to reusable functional
programs. It must reuse the current execution and resource-estimation paths.
It does not create another simulator, public serialized IR, or training stack.

The following is **proposed syntax, not executable in SYN-01**:

```python
import flagquantum as fq
from flagquantum import synth
from flagquantum.synth import Const, Output, QNum

@synth.qfunc
def polynomial(x: Const[QNum[2]], y: Const[QNum[2]], z: Output[QNum[4]]):
    z |= x * x + y

@synth.qfunc
def main(x: Output[QNum[2]], y: Output[QNum[2]], z: Output[QNum[4]]):
    synth.allocate(x)
    synth.allocate(y)
    synth.X(x[0])
    synth.X(x[1])
    polynomial(x, y, z)

program = synth.synthesize(main)
result = fq.run(program, outputs=fq.probabilities())
```

Here x=3, y=0, z=9. The shorter source earns its value only after runtime
checks prove the result, unchanged inputs, and zero workspace. Existing
two-bit handwritten Circuit evidence (18 qubits, 222 compiled gates, depth 201)
is a comparison baseline for x*x+y, not evidence that synth already works.

## Proposed surface and syntax

Names below are admitted together through review, with experimental maturity;
this proposal does not freeze a full future language or promise stable exports.
No `fq.synth(...)` synonym or decorator aliases are proposed.

| Entry | Contract |
| --- | --- |
| `flagquantum.synth.qfunc(function)` | Decorate a function; return a private quantum-function handle usable by `synthesize` and other decorated functions. |
| `QBit`, `QNum[n]`, `QNum(width=n)` | Single bit, unsigned annotation, and local symbolic register declaration. Unspecified output widths are inferred; borrowed input widths are explicit. |
| `Const[T]`, `Output[T]` | Basis-preserving borrow and produced output roles described below. Ordinary quantum parameters are mutable borrows. |
| `synthesize(entry, *, constraints=None) -> CircuitIR` | Capture, check, choose a feasible lowering, and return the existing validated IR. No execution side effects. |
| `Constraints(*, max_width=None, max_auxiliary=None, objective="width")` | Positive integer total width, nonnegative integer auxiliary limit, and `"width"` or `"depth"` deterministic ranking. Reject booleans as counts. |
| `allocate(register)` | Allocate an uninitialized resource in zero; infer a fixed annotated width or reject if unavailable. |
| `X`, `H`, `Z`, `CX` | Thin named-gate operations over initialized bit views; reuse Core opcode semantics. |
| `static_range(k)` | Nonnegative, bounded construction-time iteration. |
| `apply_circuit(block, *, qubits)` | Freeze a Circuit/CircuitIR and compose it with a total explicit injective local-to-symbolic qubit map. |
| `flagquantum.ecosystem.qmod.load_qmod(path)` | Parse the supported source into the same private entry representation accepted by `synthesize`; never execute source as Python. |
| `flagquantum.services.run_qmod(path, *, constraints=None, options=None, outputs=None)` | Compose load, synthesis, and existing `fq.run`; return the existing ExecutionResult. Execution arguments retain `fq.run` semantics. |

`from flagquantum import synth` requires explicit namespace review. Do not change
root `__all__` or regenerate API snapshots in a domain PR. The current ownership
roster has no Synth team: Compiler owns the proposed synthesis implementation;
the actual `flagquantum/synth` path admission must be recorded by Integration
before SYN-02. No ownership rule is changed by this documentation PR.

Also support the Classiq-style import form below, with the same function objects
and semantics as the qualified form. This is proposed syntax for SYN-02:

```python
import flagquantum as fq
from flagquantum.synth import *

@qfunc
def prepare(q: Output[QBit]):
    allocate(q)
    X(q)

program = synthesize(prepare)
result = fq.run(program, outputs=fq.probabilities())
```

Define `flagquantum.synth.__all__` explicitly as `qfunc`, `QBit`, `QNum`, `Const`,
`Output`, `Constraints`, `synthesize`, `allocate`, `X`, `H`, `Z`, `CX`,
`static_range`, and `apply_circuit`. Do not export private capture state,
implementation helpers, or unsupported future operations. SYN-02 must verify
that wildcard-imported names and qualified names are identical and produce the
same IR and runtime result. This familiar spelling does not promise the whole
Classiq SDK or Qmod language in the first slice. Shared code that imports other
gate libraries can use `synth.X` to avoid conflicting unqualified gate names.

Python supports positional quantum arguments, decorated subcalls, static bit
indices, aliases checked against one resource identity, local registers,
nonnegative integer literals, parentheses, `+`, `*`, and initialization `|=`.
For a fresh or proven-zero target, `z |= expression` writes the exact arithmetic
result, not bitwise OR or destructive update. The in-place method returns the
same proxy. Repeated initialization and target/source overlap are rejected.
Constant branches and bounded `for i in synth.static_range(k)` are construction
operations. Quantum truth tests, integer/index conversion, recursion, quantum
return values, variadic/default quantum arguments, comparisons, signed/fixed
point numbers, dynamic loops, general control/invert, and measurement are out
of this slice. Local Python name rebinding cannot evade ownership checks.

Capture uses operator overloading, including in notebooks, without requiring
`inspect.getsource`. Construction-time Python is trusted code, not a sandbox.
An arbitrary host infinite loop or I/O cannot be bounded by proxy checks;
the caller/environment owns cancellation. No claimed capture budget may imply
that arbitrary Python is safely time-limited.

Qmod supports `qfunc`/`main`, qbit/qnum parameters, optional output width,
`allocate`, X/H, `hadamard_transform`, nonnegative integers, parentheses,
initialization assignment, addition, multiplication, and literal square `**2`.
The transform applies H to each input bit; it is not a zero-state replacement.
Reject unknown constructs, unknown calls, and wrong arity with path/line/column.
Reject `cscope` explicitly; do not skip it and claim the file ran. `.fq` remains
reserved; no new text grammar or file renaming is part of this slice.

## Resource roles, effects, and arithmetic

* Ordinary parameters borrow initialized resources for the call. Mutable views
  may change basis values; all aliases share the same owner and lifetime.
* `Const` preserves every computational-basis label and may introduce relative
  phase. Z and CX control are allowed; X, H, or a CX target are rejected.
  This is not a promise to preserve an arbitrary superposition's complete state.
* `Output` begins without an initialized value, is initialized once by allocation
  or an arithmetic write, and is available to the caller after return. Allocated
  outputs can subsequently be passed as mutable borrows.
* Consumption-style `Input` is a future ownership transfer, not read-only input.
  It and user `free`/`drop` are unsupported here. Later checked `free` must prove
  zero before reuse; `drop` retains a possibly entangled environment and must
  never put dirty qubits in the zero pool. Internal uncomputation is distinct
  from either user operation.

Unsigned ranges propagate through expressions. Require enough bits to represent
the entire reachable range; reject insufficient explicit widths, without modular
truncation. Zero constants use at least one bit. Never specialize on a source
path, hash, or expected test answer. Classical constant folding is allowed;
independent variable multiplication tests are mandatory.

Arithmetic uses existing `adder_circuit`/`adder_qubits`, compose, and adjoint,
with new width adaptation, multiplication, and workspace scheduling. The
adder's working carry and overflow carry are distinct: only the former is
automatically clean. Copy a computed basis result coherently to a zero target,
then reverse the actual compute block. Repeated controls in a square must be
reduced legally, never emitted as duplicate-wire CCX.

`apply_circuit` requires batch size one, initialized mapped resources, static
named unitaries, and finite classical parameters. Reject measurements, reset,
channels, classical conditionals, custom matrices, training tensors, omitted or
duplicate qubits, stale/cross-capture proxies, and Const destinations. Snapshot
the block so later caller mutation cannot change the captured program. Treat
its effects conservatively; never assume its internal lines emerge clean.

## Shared boundary, layout, and evidence

Both frontends use one private source representation owned by synthesis, with
register identity/type/role, expressions, calls, initialization/gate operations,
and source locations. This carries arithmetic and effects before gate lowering;
CircuitIR is the authority once lowered. Existing hybrid SSA remains owned by
its existing subsystem; this slice does not extend it or publish another AST.
No parser-owned arithmetic implementation or generic registry is needed.

CircuitIR stays at schema 1.0. The proposed additive `metadata["synth"]` entry
has version 1, named `registers` (role, MSB-first `qubits`, unsigned width),
`workspace_qubits`, and `source` (frontend, origin and content SHA-256). Register
names are entry parameter names; internal locals are not public outputs. The
source origin is informational, not a dispatch key. Nested metadata is JSON
data and is not a second program serialization. Resource/search reports are
diagnostics, not new ExecutionResult fields; their exact extension needs review
in SYN-06. Do not claim result or plan metadata propagation until tested.

The first qubit in an unsigned register is its most significant bit. Physical
qubit 0 is the most significant axis in a flat statevector. Layouts may be
noncontiguous; use the recorded map, not a contiguous-slice assumption.
Workspace is disjoint from all live entry registers and must end at zero for
all inputs in the supported domain, including superpositions. Calling a borrowed
entry standalone uses existing runtime initial-state rules, not auto-preparation.

The service must offer named register outputs through the existing measurement
labels and result accessors, preserving the generated layout and source in
reviewed existing provenance/IR carriers. SYN-08 must test this propagation
and must not add unapproved stable result fields to work around missing access.
Joint coherent verification uses full statevectors, not separate marginals.

The contract tests in this PR use **handwritten boundary fakes**, one built with
Circuit and one directly with CircuitIR, and swap them under the same runtime
consumer. They establish that existing IR, JSON, mapping, and CPU execution can
carry the boundary. They do not implement a decorator or parser, nor prove that
future frontends emit equivalent programs. SYN-02/03 must replace these fakes
with real producers before claiming frontend conformance.

## Bounds and failures

First-slice limits: four borrowed inputs and four produced outputs (mutable
borrows count on both sides), borrowed numeric widths 1..8, output/local widths
1..64, 32 expanded arithmetic nodes, nesting depth 16, 256 expanded calls, and
256 cumulative static-range iterations. No silent partial program on exhaustion.
SYN-06 must specify and enforce finite candidate and emitted-instruction budgets
before offering constrained search; it must distinguish exhausted budget, no
candidate found, and proved lower-bound infeasibility. Defaults and diagnostics
need approval in that PR rather than being guessed in a frontend implementation.

Reuse existing errors: `TypeError` for wrong Python types, `ValidationError`
for malformed sources, effects/ownership violations and insufficient explicit
width, `CapabilityError` for unsupported syntax/operations, `CompilationError`
for bounded synthesis failure, and existing runtime errors for real execution
failure. Include the stage and source location when available. A valid captured
arithmetic operation without a lowering must raise CapabilityError, never
return an empty or placeholder successful circuit. Preserve causes and actual
execution outputs; synthesis success alone is not correctness evidence.

## Compatibility, alternatives, and rollback

Existing Circuit, compile/plan/run, result types, schemas, and API snapshots are
unchanged by this PR. No production dependency is introduced. Review namespace
names separately from implementation; root export approval cannot be inferred
from Python's ability to import submodules. Future API contracts are updated
only after review, not as an automatic test fix.

Direct handwritten Circuits remain useful but leave widths and cleanup to each
user. A string-only API would lose Python composition; a Qmod-only frontend
would exclude notebook users. Both frontends therefore converge before lowering.
Adding `.fq` syntax now or copying SDK/cloud behavior adds no necessary first
journey. Keep e-graph/CSP engines and generic managers outside this slice.

Rollback for SYN-01 removes its proposal, index entry, fixtures, and tests with
no runtime migration. Later experimental implementations can be withdrawn only
under their reviewed API status; never change existing stable contracts during
rollback. Approval and release evidence belong to their actual PR revisions.
