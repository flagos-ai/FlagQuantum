# WD-1: the documentation surface of the qubit vocabulary migration

One document per approved change to the Stable Core public API. This one records
the documentation slice that follows
[the eighth parameter slice](FQ-QUBIT-VOCABULARY-COMPILER-TOOLING-20261011.md) and
the seven before it, all under
[Quit calling them wires](FQ-QUBIT-VOCABULARY-INTEGRAL-20261005.md).

It proposes no new capability, no export, no default, and no schema. `IR_VERSION`
stays `"1.0"`. It renames no Python name: after the eighth slice the package
declares no canonical parameter, no `field` attribute, and no `instance` attribute
spelled `wire` at all. What is left is prose and examples — a surface the three
Python ledgers cannot see, and the one this slice adds a fourth ledger for.

Two things in it are worth stating plainly, because the rest of the document
defends them. First, thirteen documented keyword arguments named a parameter the
package no longer has, so the reader who copied one got a `TypeError`; the fix is a
gate that makes the class of defect fail closed, not just thirteen edits. Second,
three documented names were stale in ways that were not keywords at all, and one
was a claim the migration itself had falsified. A ledger cannot find those; reading
the pages did.

## Decision and authorization

The authorization is the one the user gave for the program: *"the user-facing
surface of FlagQuantum says `qubit`, never `wire`"*, restated in the
[integral document](FQ-QUBIT-VOCABULARY-INTEGRAL-20261005.md). This document is
recorded as `documentation_authorization` under `[verification]` in
`contracts/qubit-vocabulary-contract.toml`, and the gate checks that the path
exists on every run.

## Why the documentation is its own surface and not part of `[boundary]`

`[boundary]` refuses to include it, and the refusal is recorded in the contract:

> The boundary is the whole package, not a documented subset. A documented subset
> cannot be drawn reproducibly: matching module names in docs/\*\* turns
> `flagquantum.compiler` into its entire subtree and yields a number that looks
> precise but is decided by prefix matching.

That reasoning holds and is not disturbed here. Which module a *name* is declared in
is a fact about the AST; which prose *describes the package* is a judgement about
English, and a boundary drawn by prefix matching would be a number a reviewer could
argue with rather than recompute.

So this slice asks a smaller question instead, one that is a fact:

> **Which keyword arguments do the documents tell a reader to write?**

A documented keyword argument is an instruction. A reader copies it into a script
and expects it to run. After a rename, a document that still shows the old spelling
is the one defect class where the reader's own copy-paste is the discovery
mechanism — nothing else in the gate can see it:

- the parameter ledger reads signatures, so it is blind to a guide;
- the attribute and definition ledgers read declarations, so they are blind too;
- the string-literal report reads messages the *code* emits, so a sentence a
  document writes is outside it;
- the generated documentation renders *from* the code. `KNOWLEDGE_LIMITATIONS.md`
  and the CUDA-Q scoreboard are generated by `tools/docs_source_of_truth.py` and
  `tools/parity_matrix.py` out of `capability-maturity.toml` and the parity
  contract, so they can never quote a stale example — but they are also why fixing
  a generated page means editing its source, which this slice does.

### The prose noun

Only keyword arguments are gated. The bare noun cannot be, and the reason is that a
rule forbidding it would be switched off rather than obeyed: the documentation has
to be able to say that *CUDA-Q orders wire zero as the least-significant bit*, to
describe a `--n-wires` flag, and to write *"until workload evidence is wired into
the selector"*. Those are correct as written, so the noun is handled by reading,
file by file, and the reading is recorded here rather than enforced.

**How much of it there is.** Counting case-insensitively over every tracked
Markdown file, at the merge base and again after this slice's edits. The count is
occurrences, not lines, and the two columns come from one method so they are
comparable:

Three of those numbers need their reason stated, because a record that changed size

- `everything else` fell from 384 occurrences over 60 files to **67 over 23**, and

### The generated documentation

No generated page was hand-edited, because that is what "Do not edit by hand" means.
`docs/reference/KNOWN_LIMITATIONS.md` renders from `capability-maturity.toml` and
`docs/reference/CUDAQ_PARITY_MATRIX.md` renders from
`contracts/cudaq-parity-matrix.toml`, so the generated pages are fixed by editing
those sources — which this slice does, and which leaves
`tools/docs_source_of_truth.py --check` and `tools/parity_matrix.py --check`
passing on the regenerated output.

Editing the sources rather than the pages also caught a defect the pages had been
hiding, and a defect in the census itself. The keyword matcher required that the name
not follow a backtick, so a keyword written in a code span — ``(`wires=`)`` — was
invisible, and a backtick is precisely how documentation quotes a keyword. Dropping
the backtick from the lookbehind raises the count at the base from 13 sites to
**17**, and the four it surfaced were in two places, both of them wrong:

```
$ # the shipped matcher vs the corrected one, over the 214 in-scope files at fd4abac1
fd4abac1: shipped pattern 13 sites, corrected pattern 17 sites
   newly visible: docs/reference/API.md::wires=
   newly visible: docs/reference/CUDAQ_PARITY_MATRIX.md::wires=
```

The generated occurrence came from `contracts/cudaq-parity-matrix.toml`'s
`noise_model.static_injection` row, which documented `NoiseModel.add(..., wires=…)`
for a method whose signature is `(self, gate_names, channel, *, qubits=None)`. The
hand-written one was `API.md`'s claim that "FlagQuantum IR continue to use
`wires=`", which this slice also corrects. The pattern is now
`(?<![\w.-])(?P<name>[A-Za-z_]\w*)\s*=(?!=)`, and
`tests/unit/test_census_wire_vocabulary.py` pins the backtick case directly so the
blind spot cannot return through a future refactor.

The same contract row also taught a second keyword the live tree rejects:
`plan` and `run` reach the stabilizer engine through `options=`, not through
`state_mode=`:

```
$ FQ_WORKTREE=<tree> /tmp/n19/py -c "
import flagquantum as fq
fq.plan(fq.Circuit(2).h(0), state_mode='stabilizer')"
TypeError: plan() got an unexpected keyword argument 'state_mode'

$ FQ_WORKTREE=<tree> /tmp/n19/py -c "
import flagquantum as fq
print([f for f in fq.ExecutionOptions.__dataclass_fields__][:3])"
['mode', 'backend', 'device']
```

Both rows now read `options=fq.ExecutionOptions(mode='stabilizer')`, and the
regenerated scoreboard says so in both of its renderings.

### The caller a rename leaves behind

Reading the documentation turned up a defect that is not a documentation defect, and
it is the reason this slice adds a sixth scanned surface rather than only rewordings.

`WQ-4` renamed `execute_torch_distributed_statevector_reverse`'s `observable_wire`
parameter to `observable_qubit`. It did not rename the call. The parameter ledger
recorded the declaration moving, the attribute ledger had nothing to say about a
keyword argument, and the census's other four surfaces all read *declarations*, so
every one of them passed while this sat in the tree:

```
$ FQ_WORKTREE=<tree> grep -n "observable_wire" flagquantum/runtime/module.py
885:            observable_wire=qubits[0],
```

The call is reached only by `fq.Module.execute()` under a distributed statevector
policy, and `tests/distributed/` is not a lane any workflow here runs, so nothing in
CI would have raised it. It reproduces, and it is fixed:

```
$ # two ranks, gloo, over an explicit localhost TCP store:
$ #   set MASTER_ADDR/MASTER_PORT/RANK/WORLD_SIZE, then
$ #   torch.multiprocessing.spawn(worker, nprocs=2) where worker calls
$ #   tests/distributed/module_runtime.main() -- the body owns the process group.
$ # `torchrun --standalone` cannot rendezvous in this container; its address
$ # resolves to an all-zero IPv6 name and the store times out after 300 s.
before: TypeError: execute_torch_distributed_statevector_reverse()
        got an unexpected keyword argument 'observable_wire'
after:  {"executor": "pytorch_native_sharded_statevector_reverse_v1", ...,
         "world_size": 2} ... distributed module runtime: OK
```

`WQ-4`'s own commit message says it renamed the parameter; `module.py`'s caller was
last touched by `WQ-7`, which renamed a local variable `wires` to `qubits` one line
away and left the keyword alone. Both changes were correct on their own and the pair
was wrong, which is the shape of defect a per-file review cannot see.

**What the slice does about the class, not just the instance.** A one-line fix would
leave the next rename free to do the same thing, so the scan that found it is now part
of the gate. `tools/census_wire_vocabulary.py` gains `qubit_keyword_mismatches`, which
resolves every wire- or qubit-named keyword argument in the package against its
callee's real signature and reports the ones the callee rejects. Three decisions make
it usable rather than noisy:

- **It resolves imports over the whole tree, not the module body.** The callee here is
  imported inside the function (`from .executors.statevector import ...`), which is the
  normal style for a heavy or optional dependency, so a scan that walked only the top
  level would have reported nothing and looked clean.
- **It resolves relative imports against the importing module's own package**, with
  `__init__.py` treated as its package rather than as a submodule. Getting that wrong
  looks one level too high, skips the call, and again reports nothing.
- **It skips what it cannot decide.** A callee with `**kwargs`, an import that fails in
  this environment, a non-callable target, or a target `inspect.signature` refuses all
  yield "unknown" rather than "wrong". A gate that fires on correct code is a gate that
  gets an exemption added to it.

Unlike every other surface, this one's expected value is not a measurement but an
invariant: `[other_surfaces].call_site_mismatches = 0`, and the gate refuses a
non-zero value with the message that it is an invariant rather than a baseline. So a
future slice cannot raise the allowance to make its own change pass, which is the
failure mode a recorded count invites. The report prints it last, phrased as what it
is:

```
Qubit vocabulary call sites: 0 keywords passed that their callee rejects (invariant: 0)
```

## What this slice does not fix

Three surfaces still say `wire` where a user meets them, and none of the four
ledgers can see any of them. They are measured here so the next slice can be scoped
rather than guessed at.

### Python docstrings and comments inside the package

```
$ python - <<'PY'
import ast, io, tokenize, pathlib
doc = com = 0
for p in pathlib.Path("flagquantum").rglob("*.py"):
    src = p.read_text()
    for node in ast.walk(ast.parse(src)):
        if isinstance(node, (ast.Module, ast.ClassDef, ast.FunctionDef, ast.AsyncFunctionDef)):
            d = ast.get_docstring(node, clean=False)
            if d: doc += d.lower().count("wire")
    for tok in tokenize.generate_tokens(io.StringIO(src).readline):
        if tok.type == tokenize.COMMENT: com += tok.string.lower().count("wire")
print(doc, com)
PY
283 54
```

### A knob with no door

`docs/reference/API.md` said, and the two refusal messages behind it still say, that
a caller who exceeds the marginal-width limit can "set `max_marginal_wires`
explicitly". **No public output factory accepts that key.** The limit is a
private constant:

```
flagquantum/runtime/measurements.py:26   _DEFAULT_MAX_MARGINAL_WIRES = 8
flagquantum/observables/__init__.py:403  metadata["max_marginal_wires"] = _DEFAULT_MAX_PAULI_SAMPLE_WIRES
flagquantum/runtime/measurements.py:310  (reads the key off the request)
```

The metadata key is written only by the library and read only by the runtime, so the
documented remedy is not reachable from `fq.*`:

```
$ FQ_WORKTREE=<tree> /tmp/n19/py -c "
import flagquantum as fq
fq.run(fq.Circuit(9).h(0), outputs=(fq.probabilities(qubits=tuple(range(9))),))"
ValueError: marginal probabilities over 9 qubits exceed the supported limit of 8;
increase max_marginal_wires explicitly to raise it

$ FQ_WORKTREE=<tree> /tmp/n19/py -c "
import flagquantum as fq
print(fq.run(fq.Circuit(8).h(0), outputs=(fq.probabilities(qubits=tuple(range(8))),)).require_output('probabilities').shape)"
(1, 256)
```

The doc no longer promises a caller-settable knob it cannot find, and now says what
is true: the key raises the limit and keeps its spelling because it crosses a
request boundary. **The refusal text and the two tests that pin it
(`tests/unit/test_measurements_marginal_reduction.py`,
`tests/test_modern_measurements.py`) are unchanged and remain misleading.** Giving a
caller the door is a new capability: it needs its own proposal, its own
authorization, and a decision about whether the public spelling should be
`qubits`. It is recorded here rather than smuggled into a documentation slice.
