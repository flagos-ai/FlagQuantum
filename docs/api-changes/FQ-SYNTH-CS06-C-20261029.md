# CS06-C single synthesis workflow and named reading

Private Services integration, `single_device_fast_path`. Replace the frozen
CS04 conservative lowering and hash-only reader with the landed CS06-B selector
and CS06-A checked execution. No public synth namespace, stable API/schema,
Runtime implementation, dependency or CI changes.

The ordinary workflow remains one synthesize call, one `fq.run` and named
reading. Program retains one submitted CircuitIR for expert composition/export,
its existing arithmetic block, a brief report and optional candidate inspection.
`program.execution` supplies the already checked existing ExecutionPlan to
`fq.run(program.execution)`. Users construct no plan, mapping, candidate table or
decoder. Synthesis calls existing fq.plan once for the selected candidate and
performs no numerical execution. Reading neither plans, compiles nor executes.
This deliberately replaces the old private no-planning rule; the stronger
no-execution rule remains tested. Existing stable fq.run is unchanged.

Keep only flat user resource ceilings (max_qubits/operations/depth/workspace).
Services constructs B's existing Constraints/CircuitLimits once; there is no
second conflicting constraints parameter. ConstructionBudget is separate and
optional for expert failure control. A ceiling beyond the construction safety
cap does not increase that cap. Remove the old interpretation of final ceilings
as construction caps. Plain functions and optional qfunc keep the same semantics.

Services derives declared input names in Python signature/captured source order,
never treats arbitrary SSA namespaces as user labels, and gives names explicitly
to B. Existing named basis/uniform preparation and explicit input-only CircuitIR
preparation/maps are retained. Normal examples use no gates, physical numbers,
schedule choices or bit decoding.

Logical targets remain the default. An optional line topology profile uses the
existing CouplingMap.line factory and supported two-qubit basis when no basis is
requested. A caller-specified basis is never expanded. Services constructs the
explicit per-width table required by B, rather than making users manage it.
The line profile uses the known witness-preserving compilation policy without
final layout restore; directed/allocated/lost-witness targets remain unsupported.
This profile is not a hardware capability/native-gate claim.

Bind B's source/candidate/preparation/port identities and stage snapshots to A's
actual sealed plan. Compiler retains RuntimeConfig on its IR; Runtime canonical
program omits that annotation and retains submitted annotations with normalized
layers. Account only for this existing representation boundary and compare
existing CoreIR hashes; introduce no new serializer or fingerprint scheme.
Resource reports come from the actual checked executable. Changed source,
transform stages, logical ports, configuration or plan invalidates admission.
Equivalent existing serialization round trips are admitted through A.

The sole named reader consumes A's physical named ports and verifies the same
plan/result association. Delete the frozen CS04 route refusal and duplicate
identity/profile guard. Keep selected-bit/key/amplitude budgets before dense
marginal allocation and normalization scanning; retain finite threshold checks,
normalization refusal and omitted probability without renormalization. Decode
actual measured probabilities, not source-function predictions. Tensor forgery
authentication and arbitrary state certification are outside this boundary.

Selection failures carry B's complete report and executable recovery requests;
budget exhaustion, target limitations and final infeasibility remain distinct.
Acceptance covers high-level basis/uniform paths, constraints switching schedules,
real line routes with SWAPs/nonidentity layouts and correct named marginals,
complex phase/clean workspace, coherent direct/target gradients, stale evidence,
serialization, no hidden reading work and real repair/retry. Keep CS01-B regressions.
Independent developer trials and public admission remain future release gates;
agent-run tests do not replace those trials or prove general Qmod compatibility.

The user-facing named probability method is `program.probabilities(result, ...)`.
The earlier private `read_distribution` spelling is removed, with live examples
and tests migrated together. Return values, named registers, read budgets,
thresholds and omitted probability semantics are unchanged. This renames the
private method only; it does not admit `fq.run(program)` or sampling APIs.
