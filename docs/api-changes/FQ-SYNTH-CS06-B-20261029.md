# CS06-B finite candidate selection

Private Compiler integration, classified `single_device_fast_path`. This change
extends the CS06-A boundary without changing public exports, Runtime, stable
schemas or the frozen CS04 Services facade. CS06-C owns ordinary user integration.

Compiler enumerates exactly the existing retain and recompute schedules over one
verified definition graph. It infers contiguous named inputs and exact XOR output,
binds preparation on those input/output ports, and retains the actual CS05
allocation history. Temporary capacity is a construction budget, never a final
resource constraint. Candidates are trimmed to their actual allocated width.

The target pipeline reuses named-basis conversion, existing Compiler optimization
and persistent-layout routing, optional restore removal, post-routing conversion,
and the default Compiler normalization plus ASAP layer order used by Runtime.
The submitted program and predicted executable remain separate. The final leaf
basis, topology, layout and whole-program CircuitLimits are checked after that
normalization. Runtime remains authoritative: real seam tests compare its sealed
program to this prediction through CS06-A. No Compiler import of Runtime is added.

Named-basis conversion records, source semantic identities, candidate allocation
history, stage CircuitIR values/content identities, RuntimeConfig and existing
Layout are retained rather than introducing another serialized evidence schema.
Lost SWAP witnesses fail closed; this stage does not prove arbitrary imported
blocks or infer output mappings from `mapping_restored`. An explicitly supplied
per-width CouplingMap table represents the admitted target profiles: no graph is
silently resized, and a missing width is an unsupported target, not a fallback.
This expert configuration is not the future ordinary user API.

Final constraints have one authority: CircuitLimits for allocated width,
operations and depth; CS05 history for peak workspace. Construction capacity,
emitted/intermediate operation caps and candidate-check budgets are separate.
Any incomplete candidate evaluation caused by a budget prevents selection;
unsupported transformations remain explicit rows. Wall-clock observations do
not influence ranking, and no timeout is claimed for non-preemptible Compiler
passes. At most two candidates and the bounded existing passes are evaluated.

Ranking version 1 uses lexicographic (width, depth, operations, workspace, ID)
or (depth, operations, width, workspace, ID), with stable IDs retain=0,
recompute=1. The default width ranking must be nondominated on all four costs.
If saving at most one qubit doubles depth or operations, report the alternative
and trade-off explicitly. This is a reviewed finite heuristic, not optimality.

Every row records stage costs, construction/target elapsed observations,
workspace/recomputation, feasibility and all final violated constraints. Failure
distinguishes incomplete budgets, unsupported targets and fully checked
infeasibility. Recovery proposals relax every violated ceiling for one actually
checked candidate, retain the other constraints, and are labeled as checked-set
values rather than global lower bounds. Tests retry each proposal through the
real pipeline. A partial candidate or a best-so-far budget result is never
returned as a selected program.

Conformance replaces a deterministic Compiler target transform with a recorded
transform replay without modifying its consumer; real Runtime tests separately
verify numerical semantics. Acceptance includes the full candidate matrix for
addition, product, square-plus-add and shared-intermediate pressure at two input
widths in logical and supported named-basis targets; deterministic ranking and
constraint-driven schedule changes; whole preparation/cleanup scope; real routed
complex phases and workspace cleanup; and differentiable surrounding preparation.
Large rows are static Compiler evidence, not large dense-state execution.

The normal CS04 facade and reader remain frozen pending C. No independent human
usability trial, public synth namespace or Qmod compatibility is claimed.
