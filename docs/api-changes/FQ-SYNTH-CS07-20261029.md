# CS07 shared frontend admission boundary

Status: private cross-domain contract for review, before implementation. Baseline:
`7bb7e39c330fd6ab19ab2d598c19f1d3f3b5f1aa`, the merged #964. Classification:
`single_device_fast_path`. This milestone restores authentic source assets and
proves reuse of the existing arithmetic consumer with a recorded frontend fake.
It adds no Qmod parser, production operations, public namespace, stable API,
serializer, dependency or supported-original count. The fake is not a Qmod
implementation. Later domain implementations must synchronize this contract
before adding their respective behavior.

## Existing user workflow supported by this work

Save definitions in a Python file, then use the currently implemented path:

```python
import flagquantum as fq
from flagquantum import synth

def polynomial(x: int, y: int) -> int:
    return x * x + y

program = synth.synthesize(
    polynomial,
    inputs={"x": synth.UInt(2), "y": synth.UInt(2)},
    input_state=synth.InputState.basis(x=3, y=2),
    max_qubits=18,
)
assert dict(program.probabilities(fq.run(program))) == {(11,): 1.0}
```

`python -m examples.algorithms.synthesis_trial` runs the existing complete
basis, uniform and line workflows. CS07 must reuse their construction,
constraints, execution and reading authorities rather than replace them.

## Responsibility and representation

| Boundary | Owner and required reuse | New work still required |
| --- | --- | --- |
| Source text, native grammar, upstream version and diagnostics | Ecosystem; source locations use existing SourceLocation/Diagnostic | Bounded offline parser, name resolution and an explicit supported-syntax check |
| Numeric expressions | Compiler; existing HybridProgram/Region/Block/Value/Operation, quantum.uint, INDEX, qint operations, range checks | Translate accepted source expressions into this same verified model; no Python string execution or generated callable |
| Ordered quantum preparation and output initialization | Compiler; existing model/effect token and Core instructions; reuse shared arithmetic kernels and scheduling | A verified register-initialization/composition profile for fresh outputs, multiple live outputs and ordered X/H preparation |
| Physical maps and source numeric weights | Compiler; existing binding/layout authorities | Explicit source-index-to-MSB-first-register mapping, validated before use; retain it through layouts and named reading |
| Construction budgets, retain/recompute, target constraints | Compiler; existing finite candidate selector, target pipeline, limits and resource estimator | Extend their whole-program scope to the admitted preparation/output profile |
| Program composition, actual execution and named results | Services; existing checked-plan and readout authority; Runtime unchanged | Compose the accepted external frontend through the same authority once the Compiler profile exists |

A parsed syntax tree belongs only to the adapter. No Classiq SDK objects enter
Compiler/Core/Runtime. Do not create another generic SSA, pass manager, backend,
executor, source-hash validator or per-file circuit generator. The existing
arithmetic profile deliberately rejects general gate/effect operations; its
borrowed inputs and one return cannot silently stand for fresh output objects.
Existing hybrid quantum.x/quantum.h operations demonstrate model vocabulary,
not a verified allocator or an implementation of register-level construction.
The Compiler implementation must first settle the smallest necessary private
operation/initialization rules in the existing model and test both frontends
against them. This contract does not freeze speculative new operation names or
claim that existing verification already accepts them.

## Required quantum semantics

- Preserve declared dimensions and output names. A qbit has one bit; qnum<3>
  keeps three bits. Infer omitted qnum representation from documented numeric
  rules and type ranges, with a separately recorded decision; do not infer a
  narrow type merely from one observed run or overwrite source declarations.
- Output is uninitialized on entry. allocate makes a fresh zero register;
  out-of-place `=` requires an uninitialized destination and initializes it.
  Repeated initialization, reads before initialization and double allocation
  fail before gates are emitted. Constant initialization creates quantum output
  storage; it is not an alias for a classical INDEX constant.
- `X(q)` and `hadamard_transform(x)` are ordered quantum operations. H is not a
  classical uniform sampler. All controls and relative phases must survive.
- Existing arithmetic uses full-width XOR into a separate target. Fresh `=` may
  consume that primitive only after establishing the target-zero obligation;
  general initialized-target XOR, truncation and modular addition stay rejected
  until their own explicit width rules are implemented.
- Source bit index i has numeric weight 2**i; a destination MSB-first register
  of width w maps that source bit to register[w-1-i]. Do this per numeric view,
  never by reversing the complete circuit, a printed key or a wire list by name.
  Slice/bind/QArray probes must be asymmetric and labelled synthetic until
  those features are admitted. Keep actual layout transformations independent.
- Plain source quantum parameters, Input consumption and Const restrictions are
  distinct effects; the last two are not aliases for immutable arithmetic input
  or compile-time integers. Initially reject them explicitly. Likewise reject
  free, drop, bind, cscope, control/invert/within-apply, signed/fixed numbers,
  arrays/structs, dynamic flow and unsupported functions rather than skipping
  them. A future adapter may expand this set only with semantics and evidence.
- Returned source outputs stay live. Only compiler-owned, inverse-cleaned
  temporary workspace can be reclaimed. No measurement/reset or hidden state
  discard is permitted to make cleanup appear successful.

The [official-semantics review](../roadmap/CLASSIQ_SEMANTICS_REVIEW_20261029.md)
records the assignment, quantum-type, role and cleanup references. The corpus
pins an older upstream revision; current documentation is context, not evidence
that a historical spelling or signature was accepted. Any difference needs a
versioned diagnostic and explicit decision in the adapter's source record.

## Replacement and numerical acceptance

`test_synthesis_qmod_source_contract.py` substitutes a recorded HybridProgram
producer for Python capture behind one unchanged verifier/lowering consumer.
Both retain and recompute schedules execute on actual CPU with all four
reduced-width basis components in superposition, nonzero XOR output, controlled
relative phase and zero workspace. This proves the existing arithmetic seam can
serve another producer; it proves no native grammar or original-file support.
The original three-bit tutorial is never replaced by this two-bit probe.

Before counting an original as verified, execute its unmodified source and
compare the full complex state to an independent analytic reference, including
live output names/weights and zero workspace. Preserve the declarations:
X -> q=1; tutorial -> eight amplitudes at (x, x*x+1), each 1/sqrt(8);
multiplication -> (a,b,res)=(4,5,20) with amplitude 1. Record inferred widths,
logical/physical maps and actual final resource costs; do not certify a value
only from a probability dictionary. Refuse impossible test allocations before
execution. Structural large-circuit checks, analytic formulas, reduced probes,
parser success and CPU simulation are separate evidence tiers.

Also test wrong initialization, unknown calls, unsupported roles/types/effects,
malformed syntax, source size/token/depth budgets, asymmetric indexing, invalid
bindings and loss of source/target evidence. Reuse existing result-association,
read budgets and normalization refusal. No SDK/cloud access is needed for CI.

## Delivery sequence

1. CS07-A (this PR): original assets, seven digest checks, current-gap record,
   shared consumer replacement tests and independent-developer handoff.
2. CS07-B (Compiler): admit the minimal common initialization/preparation and
   output-composition profile, using existing types and kernels. Demonstrate
   it from an independent program producer; preserve current Python behavior,
   all phases, nonzero XOR semantics and clean workspace. No public API change.
3. CS07-C (Ecosystem): bounded native parser to the admitted model; exact source
   locations, roles, numeric weights and diagnostic refusal. Test general syntax
   combinations, not a filename/text-hash switch or a function per original.
4. CS07-D (Services/integration after the shared boundary lands): use that
   frontend through existing construction/execution/readout; validate all three
   original files at declared sizes, separately report parsed/lowered/executed/
   verified counts. Any new public external-source entry needs its own API
   proposal before export. No Services.run_qmod or .fq parser is added here.

CS06 independent developer trials can run against merged #964 while these
private prerequisites proceed. Their absence blocks release approval, not
honest source-integrity or private boundary work. Neither source checks nor
agent-run seam tests fill those human records.
