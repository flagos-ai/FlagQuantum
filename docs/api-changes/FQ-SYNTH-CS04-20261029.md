# CS-04 private Python trial boundary

Status: private implementation proposal for review under revision-six CS-04.
The user requested this trial and a PR. This record does not approve, freeze or
modify any stable public API. Public `flagquantum.synth`, root exports, serialized
schemas and ExecutionResult fields remain unchanged.

## Responsibilities and existing contracts

Compiler owns restricted source capture in `_construction/frontend_python.py`.
It produces the existing HybridProgram and verified construction profile.
Constants, source locations, full-width unsigned inference and coherent XOR
lowering reuse CS-01 through CS-03. Helpers are explicitly registered and inlined;
there is no new IR, interpreter or generic function registry.

Services owns `_synthesis` and `_synthesis_readout`, composing that private
Compiler seam with existing CircuitIR, compile/resource estimation, ExecutionPlan
and Runtime probability reduction. These are intentionally private integration
seams requiring review in this PR, not a new stable contract. Runtime and
Simulation implementations are unchanged. The classification is
`single_device_fast_path`; no distributed, accelerator or hardware claim follows.

## Trial entry

```python
from flagquantum.services import _synthesis as synth

def compute(x: int, y: int) -> int:
    return x * x + y

program = synth.synthesize(
    compute,
    inputs={"x": synth.UInt(2), "y": synth.UInt(2)},
    input_state=synth.InputState.basis(x=3, y=2),
    max_qubits=18,
)
```

`synthesize` takes explicit `inputs`, optional `input_state`, nonnegative plain
integer `constants`, explicit helper `functions`, `max_qubits=256` and
`max_operations=100000`. An advanced mutually exclusive `preparation` CircuitIR
and `preparation_map` connect existing input circuits. `qfunc` is optional and
captures source earlier; ordinary functions retain normal host-call behavior.

The private Program contains existing `circuit` and `arithmetic` CircuitIR,
named register layout and logical resource report. Only the advanced arithmetic
composition path requires physical bindings. `read_distribution(result, *,
registers=("result",), max_bits=16, max_keys=65536,
max_amplitudes=4194304, threshold=1e-14)` returns a read-only mapping from UInt
tuples to probabilities, with separate read/filter diagnostics.

## Identity, failure and migration boundaries

Synthesis precomputes the default compiler schedule identity using Compiler APIs.
Reading verifies the original source hash and both Runtime plan program hashes;
matching width alone is insufficient. Content-identical JSON round trips work.
Routed, noisy, transformed, missing-plan or stale results fail explicitly. The
reader does not execute, recompile, replan or mutate the product report. It uses
existing Runtime analytic probability reduction on the supplied state tensor.
Plan association is checked; manually forged result tensors are not authenticated.

Only one normalized materialized complex64/complex128 CPU statevector is accepted.
Budgets are checked before the norm scan and dense marginal allocation. Values
at or below threshold are omitted and their mass is reported without
renormalization. The distribution is not a differentiable training output.

Discrete domains, constants and preparation are structural; trainable tensors
are rejected. Existing parameterized Circuit composition with `arithmetic`
retains the existing angle-gradient workflow. General routing-aware result
revalidation belongs to later work, not an implicit acceptance here.

Before public promotion: settle names and declarations with user trials, obtain
public API approval, define migration/versioning, and extend exact result-layout
conformance. No stable snapshots are modified by this PR.
