# IR-002: Linear Qubit Values in QuantumIR

Status: Approved
Date: 2026-09-01
Applicable phase: Phase 1 QuantumIR core, verifier, and importer.

Approval record: the API owner explicitly approved IR-001 through IR-003 on
2026-09-01. Approval covers the internal QuantumIR linear value model only. It
does not change the public imperative `Circuit` experience or `CircuitIR` wire
representation. Implementation still requires compiler owner review and Phase 1
verifier acceptance.

## Background

Current `CircuitIR` represents imperative circuits using integer wires and ordered
instructions. Internal QuantumIR needs explicit dataflow to verify lifecycles,
rewrites, schedules, and future dynamic control, without implying that quantum
states can be copied.

## Decision

Phase 1 QuantumIR uses linear values:

```text
%q1 = quantum.h %q0
%q2, %q3 = quantum.cx %q1, %q_other
%q4, %m = quantum.measure %q2
```

Rules:

- Import creates one unique initial qubit value for each logical wire.
- Each gate consumes its operands' current values and produces new values in wire order.
- A consumed value cannot be used by another quantum operation.
- A multi-qubit gate produces one successor per input, preserving operand/result
  wire ordering.
- A value is a resource version at a program point, not a statevector, and cannot
  be copied.
- A canonical importer generates `ValueId` deterministically.
- Phase 1 has no control flow; verification covers a single-block linear chain.
- Operation schemas explicitly state whether a qubit remains usable after measurement.
- Future block arguments/phi-like joins must preserve linear ownership but are
  not implemented in Phase 1.

## Required Phase 1 Verifier Rejections

- Two quantum operations consume the same qubit value.
- A gate is followed by use of an old value.
- Incorrect operand/result arity or qubit types.
- Two logical resources incorrectly mapped to one value.
- Use after release or terminal consumption.
- Qubit values placed in ordinary attributes/containers without linear semantics.
- Discontinuous or nondeterministic wire/value mappings generated by the importer.

## Rejected Alternatives

### Continue Using Only Integer Wires

Ownership, def-use, and future control-flow joins would not be directly verifiable;
passes would tend to depend on implicit order.

### Treat Qubits as Ordinary SSA Values

Ordinary SSA permits repeated reads, incorrectly implying copyable quantum resources.

### Implement General-Purpose SSA Immediately

This exceeds static-circuit verification needs and adds implementation and
maintenance risk.

## Compatibility and Rollback

Linear values exist only in internal importer output. Public `Circuit` remains an
imperative builder and public `CircuitIR` retains integer wires. Removing
`_compiler` does not affect user code or persisted objects.

## Acceptance

- Every Phase 0 static fixture produces a deterministic value chain.
- Negative fixtures cover duplicate consumption, stale values, and incorrect arity.
- Round-trip preserves original instruction/wire order.
- State, expectation, and gradient differential tests pass.
