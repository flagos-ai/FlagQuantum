> sliced, or planned execution path is not distributed scalability evidence.

## How to read maturity

| Level | Meaning |
| --- | --- |
| **Release certified** | Release-gated with audited, reproducible evidence and no unresolved release blocker. |
| **Production supported** | Supported path with compatibility, operational guidance, and target-hardware evidence. |
| **Development evidence** | Executable and tested development result; not a production or general scalability claim. |
| **Experimental** | Research surface without compatibility or production guarantees. |

- **Public API:** `fq.Circuit`, `fq.CircuitIR`, `flagquantum.compiler.compile`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../examples/quick_start.py)
- **Documentation:** [guide](../../docs/reference/API.md)
- **Known boundary:** IR v1; incompatible schema changes require an explicit migration.

### Program optimization and target-aware compilation

Transform one FlagQuantum IR program without executing it: canonical optimization, logical layer scheduling, and lowering onto an explicit coupling topology.

- **Maturity:** Production supported
- **Public API:** `flagquantum.compiler.optimize`, `flagquantum.compiler.compile`, `flagquantum.compiler.route_to_topology`, `flagquantum.compiler.schedule_layers`, `flagquantum.compiler.CouplingMap`, `flagquantum.compiler.plan_trivial_layout`, `flagquantum.compiler.plan_dense_layout`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../examples/compiler_optimize.py)
- **Documentation:** [guide](../../flagquantum/compiler/README.md)
- **Known boundary:** In-process transformation of one FlagQuantum IR v1 program on CPU; the compiler never executes a program or certifies hardware behavior. optimize() runs a named, ordered sequence of ten pass calls to a fixed point: it removes identity gates, merges self-inverse runs, merges adjacent rotations, removes resets on a wire still in the zero state, cancels declared inverse pairs and self-inverse pairs separated only by a proven commuting gap, drops diagonal gates before a measurement, and folds one-qubit runs. That sequence is resolved through a registry that also carries the analyses the passes read: two program-independent facts (the self-inverse opcode set and the rotation-parameter table) are computed once per fixed-point run, and the commuting-block partition is computed only if the pass that declared it reaches the point of asking. A pass that reads a carried fact without declaring it preserves it is refused before any pass runs. compile() runs that same fixed point, optionally routes onto one explicit CouplingMap, optimizes again, and records post-routing optimization. Routing offers four caller-selected strategies: restore_after_each_gate, persistent_layout, sabre, and sabre_layout. All four restore the identity logical order at the program output, so a caller cannot ask for an unrestored final permutation, and every one of the four is priced by the cost estimate, so the automatic selection can reach the SABRE planner. Its candidates are the three the deployment routing contract accepts: restore_after_each_gate, persistent_layout, and sabre. sabre_layout is caller-selected only, because it starts from a layout its own search chose and so does not always begin from the identity logical order a deployment artifact has to state; a provider that accepts a permuted starting assignment can still request it by name. The topology is always caller-supplied and never discovered. Initial placement is planned separately: plan_trivial_layout places logical wire i on physical wire i, and plan_dense_layout places the program on the most densely connected window of device wires a breadth-first walk from every physical wire finds, which is the only placement that can help on a device with unequal connectivity and the only one of the two that can reach a program the lowest wires cannot hold at all. That walk is a heuristic and not an exact optimum: over 55 device and program-width combinations it matched an exhaustive search of every connected window 45 times and returned a window with one fewer internal connection the other 10 times. Both return a placement as a tuple of physical wires, one per logical wire, which is what route_to_directed_topology takes as initial_layout; final_layout reports the assignment a routed program ended on as a Layout, and a route that allocates workspace on a device wider than the program reports the device width there with its idle slots as None in physical_to_logical. Both placements collapse to the identity on a device no wider than the program. The three undirected entries price and route against a weak connectivity and do not read CX direction: estimate_routing_cost, select_routing_strategy and route_to_topology each refuse a DirectedCouplingMap by name rather than iterating it, and name legalize_circuit_topology as the entry that does read direction. Neither reaches route_to_topology, which refuses an initial_layout because a plain CouplingMap routes only over wires the program owns; a non-identity placement requires a DirectedCouplingMap, whose physical workspace owns the idle slots and is cleaned by the inverse routing SWAPs, and it is passed to route_to_directed_topology or to legalize_circuit_topology. remove_layout_restore drops the appended logical-restore phase from a program that was already routed, halving the SWAP count over a batch of random programs for persistent_layout because that strategy's restore is a full reverse replay of its forward SWAPs and leaving restore_after_each_gate unchanged because its restores are interleaved with the program, and its result is a program for a local simulator or a provider that accepts per-physical-wire results rather than deployable routing evidence: the deployment routing contract rejects it and the deployment entry points treat it as unrouted and route it again. Window selection is greedy over device connectivity and never estimates routing cost, so it can cost more SWAPs than the trivial placement on a program whose interactions prefer a sparser window, and it is not noise- or calibration-aware. Scheduling constructs deterministic logical ASAP layers with explicit wire and classical-data dependencies; it is not target timing or pulse scheduling. There is still no directed acyclic graph intermediate and no pass analysis or preservation metadata. The fixed optimization sequence is now a named, ordered pipeline behind an immutable pass registry: every step is a resolved name, a sequence is resolved in full before the first pass runs, the built-in names are reserved so an added pass cannot shadow one, and the number of rounds the fixed-point loop runs is unchanged. A third-party pass reaches compilation through the ecosystem crossing that admits a negotiated compiler_pass extension and registers its transform under a name prefixed with the supplying extension; that crossing is host-side and the admitted pass is never added to the pipeline compile() is defined by, so installing a plugin does not change what the public compile and optimize entry points do. The registry, the manager, and the crossing are Compiler-internal rather than public API, and the only host-facing reach is the explicit entry point that runs the built-in pipeline and then one admitted pass. An installed external compiler is still selected by name through the extension SDK rather than composed as a pass. Pulse-level, calibration-aware, and parameter-aware compilation, dynamic-circuit control flow, and noise-aware optimization beyond lower_noise_model are unsupported. The structured hybrid program slice under flagquantum/compiler/_hybrid is private and absent from public exports. Compilation is single-process; no distributed or multi-device compilation path exists. A rotation whose angle is an exact multiple of pi/4 is expressible on a target that publishes only named Clifford+T gates: the exact quarter-turn words are a candidate rewrite in the basis search, the first word of each residue carries the fewest T gates, and a fallback word keeps every residue reachable when the target omits one of an inverse pair. An angle outside those multiples is refused rather than approximated, so there is no accuracy-directed angle synthesis and no target-accuracy parameter, and reaching an arbitrary angle needs a Ross-Selinger-class approximation over exact arithmetic that this repository does not carry.

### Construction-time program composition

Build a larger program out of smaller ones in place: place one program on chosen qubits, and invert a program, without introducing a second IR.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.Circuit.compose`, `flagquantum.Circuit.adjoint`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../docs/reference/API.md)
- **Documentation:** [guide](../../docs/reference/API.md)
- **Known boundary:** Both methods are Stable Core additions to the fq.Circuit type, approved by docs/api-changes/FQ-CIRCUIT-COMPOSITION-20261002.md and docs/api-changes/FQ-CIRCUIT-ADJOINT-20261003.md, and the surrounding family is incomplete. Circuit.compose accepts a Circuit or a CircuitIR and appends the other program's instructions to the receiver, rewritten onto the qubits the caller names; with neither argument the placement is the identity over the source width. Composing appends rather than assigns, so a target qubit that already carries instructions is legal and is not overwritten, while two source qubits may not share one target. Placement is explicit and fail-closed: qubits and qubit_map are mutually exclusive, a map must name every source qubit, a repeated, negative or out-of-range target is refused, and mixing batch sizes is refused rather than broadcast. A noise channel, a dynamic operation, a classically conditioned instruction, a matrix without a conjugate transpose and an unknown opcode without a matrix are each refused with CapabilityError rather than copied forward. Composition is a rewrite of qubit labels and not a second program description: neither method changes IR_VERSION, both emit instructions the IR already describes, and neither adds a root export, so no existing program changes meaning. control and power belong to this family and are absent: neither has an approved API change proposal, so a multi-controlled or exponentiated form is an owned gap rather than an unimplemented detail. The surface is single-process CPU work on one program with no execution, compilation, routing, noise handling, or scalability claim, and it is not differentiable by itself because composition records instructions rather than evaluating them. contracts/circuit-composition-contract.toml is the authoritative list of these guarantees and of every refusal, and tests/unit/test_circuit_composition_contract.py reads it back against the implementation.

- **Distribution semantics:** `not_applicable`

- **Documentation:** [guide](../../flagquantum/compiler/README.md)
- **Known boundary:** Text interchange only; the importer never executes a program and does not make FlagQuantum an OpenQASM front end. Both 2.0 and 3.0 are read; the version and its matching include statement are mandatory, so a program declaring any other version is refused as unsupported_version. - **Documentation:** [guide](../../docs/guides/NOISY_SIMULATION.md)
- **Known boundary:** Validated Markovian Kraus channels, timestamped DeviceNoiseProfile input, ASAP gate/idle thermal lowering, classical readout confusion, exact density execution, batched statevector trajectories, and reproducible MPS trajectories with single-rank adaptive stopping are available. Four channel opcodes (bit_flip, phase_flip, depolarizing, amplitude_damping) declare the scalar their factory takes, so they can be written directly into a circuit as well as attached to a gate through a NoiseModel rule; the two routes lower to the same instruction, and a program is planned as noisy because it carries a channel, not because a model was passed. That same reading of the program decides the trajectory representation under mode='auto' and restores it from a saved plan, so an inline channel and an equivalent NoiseModel rule select the same route. A representation that holds amplitudes -- mps, tensor_network, and statevector -- refuses a channel instead of returning the noiseless number, and mode='stabilizer' samples the frames the channel defines rather than applying an operator it cannot hold, refusing only a request for an exact value on such a program or a channel outside the Pauli-frame class. A channel instruction's matrix field is the Kraus tuple, so consumers read it as a sequence rather than as one tensor. Only those four opcodes are reachable by name: the remaining flagquantum.noise callables, including thermal relaxation, readout error, and coherent overrotation, are NoiseModel rules only. Channel parameters are bound real scalars; a trainable channel probability has no gradient path. Lowering refuses a rule naming a wire outside the program width and refuses a model whose rules match no instruction at all, so a misspelled gate name cannot yield a clean result; a model that matches some instructions stays legal. The three kernels count their own events, so which one ran a channel is read from the result rather than assumed, and a route that asks the classifier takes the same estimator as the generic route: on this box the two routes return bit-identical states at the same seeds. The exact density-matrix route sums the whole channel whether or not it is a mixture, so it is the one consumer that does not read the classification, and no planning, scheduling, or memory-budget decision is taken from it. Pulse overlap, crosstalk, leakage, provider calibration adapters, distributed adaptive stopping, production multi-GPU scheduling, and noisy gradients remain unsupported. Multi-wire MPS channels use an explicitly dense correctness fallback. ### Continuous-time Lindblad density-matrix evolution

- **Maturity:** Production supported
- **Public API:** `flagquantum.lindblad.run`, `flagquantum.lindblad.plan`, `flagquantum.lindblad.LindbladPlan`, `flagquantum.lindblad.amplitude_damping`, `flagquantum.lindblad.INTEGRATOR_NAMES`, `flagquantum.lindblad.adjoint_gradient`
- **Runtime modes:** `continuous_time_density_matrix`
- **Hardware:** `cpu`
- **Gradient support:** `exact_autograd_through_the_integrators`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../examples/lindblad_evolution.py)
- **Documentation:** [guide](../../flagquantum/simulation/README.md)
- **Known boundary:** Time-independent Hamiltonian representations, dense or matrix-free Pauli sums, finite strictly increasing grids, Markovian Lindblad collapse operators, and CPU complex64/complex128 execution only. The integrator is selectable between explicit fourth-order Runge-Kutta, the second-order implicit Crank-Nicolson trapezoidal rule and a matrix-free exponential scheme. The two order-p schemes each take two substeps per output interval; the exponential scheme takes the interval whole, because the exponential of a time-independent generator is exact on the grid, so it reports no order and its accuracy is set by solve_tolerance instead. Both Krylov schemes apply the generator rather than forming it: Crank-Nicolson through restarted GMRES, the exponential through a single Arnoldi window whose projected exponential is the only exponential computed, so neither allocates the 16-to-the-n vectorized generator. The relative residual or defect target defaults to 1e-12 in complex128 and 1e-5 in complex64, it is refused for the explicit scheme rather than ignored, and a step that misses the target fails the evolution as integration_not_converged. For reference and for the properties that are statements about it, Liouvillian materializes the vectorized generator on demand but refuses to above a declared 16 MiB ceiling, which admits five wires and refuses six. A state may carry a batch axis -- a batch of statevectors as (batch, dim) or a batch of density matrices as (batch, dim, dim) -- with (dim, dim) keeping its reading as one density matrix; batch_size is refused when it contradicts the state, and the batch axis is folded into the solved Krylov vector rather than looping over members. The integrators are ordinary differentiable tensor operations, so a trajectory parameterized through either the Hamiltonian or the initial state carries an exact autograd graph, and the matrix-free solves keep the norms that scale their basis and result on that graph; require_gradients=True is decided on the returned trajectory and a detached one is refused as gradients_not_available. The gradient is that of the discretized evolution, not of the exact solution. flagquantum.lindblad.adjoint_gradient additionally returns a reverse-mode cotangent through that same discrete scheme: the forward sweep retains the output trajectory under no_grad and the reverse sweep applies the Hilbert-Schmidt adjoint of the vectorized generator, so no forward graph is kept and the cotangent is the conjugate transpose of the scheme the caller named rather than of the exact solution. The reverse map is the Hilbert-Schmidt adjoint of the generator that was assembled, `SuperOperator.adjoint()`, so the forward and reverse maps are one term list read in two directions; it is verified against the Liouvillian's own dense conjugate transpose and by the pairing identity between the two, and a matrix-free Pauli-sum Hamiltonian is reversed without being materialized, because `PauliSum.adjoint()` conjugates its coefficients and leaves the Hermitian strings alone. The route refuses require_gradients=True, a cost that is not callable, and a cost that does not return a scalar, and its cotangent follows the complex-gradient convention in which a perturbation pairs with it through the real part of the inner product of its conjugate with that perturbation. One measured property of the forward path is disclosed here rather than repaired: at a base point where the two routes differ most, the adjoint route reproduces the dense transpose of the scheme it was given to roundoff, while the backward pass through the matrix-free solve is an approximation of that transpose -- relative to a five-point stencil of the same scheme it is 3.5e-06 away for Crank-Nicolson and 1.7e-05 for the exponential scheme, where the adjoint route is 1.0e-10 and 8.9e-11 away, and a finite difference of one Crank-Nicolson interval agrees with that scheme's dense transpose to 4.6e-11 where autograd's cotangent is 5.7e-08 away from it. The explicit scheme, which takes no solve, is at roundoff on both. That gap is the conditioning of the discretized generator rather than a defective vector-Jacobian product, because the matrix-free solve's own backward is exact to 1.7e-15 on a well-conditioned system. Non-Markovian environments, stochastic trajectories, sparse solvers, GPU/distributed execution, hardware submission, and arbitrary time-dependent generators are unsupported. Integrator selection is covered by tests/unit/test_lindblad_integrators.py, the vectorized generator and exponential step by tests/unit/test_lindblad_vectorized_generator.py, and the batch axis and gradient path by tests/unit/test_lindblad_batching_and_gradients.py. The adjoint cotangent, its agreement with the dense transpose of each scheme and its retention claim are covered by tests/unit/test_lindblad_adjoint_gradient.py. The superoperator algebra beside this route reads a map's Choi matrix through `flagquantum.operators.SuperOperator.choi`, in the index order `J[(a, i), (b, j)] = E(E_ab)[i, j]`, and certifies complete positivity through `is_completely_positive`, which is the eigenvalue test that separates amplitude damping or dephasing from the transpose map; that certificate reads its tolerance relative to the Choi matrix's own spectral scale because the absolute rounding error grows with the dimension and the entries, reaching 1.337e+06 epsilons in complex64 and 9.956e+05 in complex128 on a rescaled channel whose smallest eigenvalue is exactly zero. A map that does not preserve Hermiticity -- an anti-Hermitian generator, for instance -- is refused by name rather than reported as not completely positive. Both normalization conditions are public accessors rather than recipes: `SuperOperator.partial_trace` sums one of the two registers of the Choi index order, so its `input` register is `E(I)` -- the identity exactly for a unital map -- and its `output` register is the identity exactly for a trace-preserving one. The two are separated by a map that is trace preserving and not unital, which is what amplitude damping is, and the accessor adds no arithmetic of its own: it is the same sum the owning suite measured by hand, now named and refused by name for a register that is neither. The algebra also reads a Kraus list back off that matrix rather than only accepting one: `SuperOperator.kraus` diagonalizes the Choi matrix and weights each eigenvector by the square root of its eigenvalue, so a channel that arrived as a matrix, a term list or a Lindblad route leaves as a Kraus list, and three operators spanning two dimensions come back as two. It is the count and the map that are pinned rather than the individual operators, because the eigenvector phases belong to the eigenproblem; the unstacking index order is not free, and dropping its transpose is measured 2.625e-01 away from the map's own action on amplitude damping at gamma = 0.4, where the `[0, 0]` entry of that candidate is exactly `-gamma * rho[1, 1]`. The round trip through `from_kraus` returns the map to 5.594e-17 at two levels and 1.665e-16 at three, and to the worst of 1.788e-07 over every fixture in complex64, which is the dtype's rounding rather than the decomposition's. A map whose Choi matrix has a negative eigenvalue is refused by name with that eigenvalue, because no Kraus list denotes it and the closest one would be a different map -- the transpose map's is exactly -1.000000 against a scale of exactly 1.000000. The byte ceiling, the Hermiticity refusal and the tolerance are the choi certificate's rather than a second set, so the two methods answer from one eigenproblem and one rule.

### Stabilizer-code memory circuit

- **Maturity:** Development evidence

- **Runtime modes:** `local_statevector_dynamic_hybrid`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../flagquantum/qec/README.md)
- **Documentation:** [guide](../../flagquantum/qec/IMPLEMENTATION.md)
- **Known boundary:** A code-independent declaration layer, not a decoder and not an experiment runner. build_memory_circuit emits bounded hybrid source text plus detector and observable layouts; executing that source is the Runtime's dynamic hybrid path and carries that path's own limits. Six code records exist: the repetition code, the rotated surface code, the Steane code, which is the first record carrying both a Z-type and an X-type logical observable, the triangular colour code, whose checks are the first here that reach weight six, the square-lattice toric code, which is the first record whose matrices leave more than one logical qubit and whose lattice is periodic rather than a patch, so its linear size is the distance the build must prove, and the ZXXZ surface patch, which is the first record whose every check is mixed and none is pure, so it is stated as the rotated patch conjugated by a Hadamard on the data checkerboard and is reached only through this route, never through the matrix route. The repetition, rotated-surface and Steane records keep the evidence their own test files carry unchanged; the colour record's own evidence is tests/qec/test_colour_code.py for the lattice and tests/qec/test_colour_memory_execution.py for the executed experiment, sampling and decoding of the patch, and the torus's is tests/qec/test_toric_code.py for the lattice algebra, including the logical-qubit count measured from the rank of its own rows, and tests/qec/test_toric_memory_execution.py for the executed experiment, the sampler comparison per observable index and a decode; the ZXXZ patch's is tests/qec/test_zxxz_code.py, which re-derives the conjugation from the rotated patch's own checks rather than repeating the record's claim, measures the family's distance by exhausting every pure operator below it, and shows the choice of checkerboard parity is load-bearing, and tests/qec/test_zxxz_memory_execution.py, which measures the readout limit from both sides and asserts the decoded-against-raw contrast against the rotated patch at the same distance, rate, budget and seed. Graphlikeness is not a property of a code here: the torus's one-round model is graphlike under any noise and its two-round model stops being graphlike once a Y data fault is declared, and the latter is measured beside the former rather than recorded as a refusal alone. A check states one ancilla and one coupling order: the Z-factor pairs first, each reading a data wire into the ancilla, then the X-factor pairs, each reading the ancilla out into a data wire. A mixed X-and-Z stabilizer is therefore measured by one ancilla and both CNOT directions, and the earlier reading that such a check would need a second ancilla is retracted; the second direction is what a mixture needs and the second ancilla is not, and a pure check is the case whose second run is empty. What that costs is recorded rather than hidden: a mixed check's outcome is deterministic neither at the all-zero preparation nor at a Z-basis readout, so the Z-basis memory experiment of a code whose checks are all mixed carries detectors only between syndrome rounds and none from a syndrome round to the data. Such an experiment has a mechanism at every distance that fires no detector and flips the observable -- the readout, merging the logical operator's d wires into one mechanism of probability (1 - (1 - 2p) ** d) / 2 -- whose probability grows with the distance and which no pairing decoder can suppress, because there is no detector to pair. On that code the matching decoder reproduces every syndrome it is handed and still leaves the decoded rate above raw / 1.5 at distances three and five, against raw / 4 or better for the rotated patch through the identical harness, so such a patch is not yet a distance-d memory experiment in the sense the rotated patch's is. Both the initial state and the terminal data readout are in the Z basis unless a logical product is declared, in which case build_memory_circuit inserts a Hadamard on exactly the product's X wires before the round loop and again before the terminal readout, so one code record can be read out in either Pauli basis without a second circuit shape. A declared product must be a pure X-type or a pure Z-type Pauli operator over declared data wires; a mixed X-and-Z product is refused, because a Y factor would need a second rotation axis on that wire, and so is a product that does not commute with every check, or that lies in the stabilizer span of the observables of its own type, because such a product is a stabilizer rather than an observable. The partner of a declared observable is derived rather than chosen: derive_anticommuting_logical_product solves the code's checks of the opposite type together with its declared observables of that type over GF(2) and refuses when the code has none, so a repetition patch of even distance offers no X-basis readout and states the reason instead of half-reading. Detector counts follow the two check classes, z_checks * (rounds + 1) + x_checks * (rounds - 1) in the default frame. A rotated readout frame keeps a boundary detector only for an X-type check whose support lies inside the rotated wires and for a Z-type check whose support is disjoint from them, and keeps every round-to-round detector either way; an experiment whose configured rounds leave no deterministic detector at all is refused with the round count named as the remedy rather than emitted empty. Counts are validated against the code's checks and the configured rounds, but the validation is membership-based: it does not check that a detector names the same check in every round, that a terminal detector's data wires are the support of the check it belongs to, or that the emitted source is the program the layouts describe, so a hand-built layout can be semantically wrong while passing every check. The rotated surface code's declared logical observable is Z on one data row; which weight-d logical operator a patch uses is a convention, and this record states the one it uses rather than deriving all of them, while its X-basis partner is derived and certified rather than chosen. Certification is a statement about the operator and not about a probability: a certified product is not thereby a corrected logical qubit, and no protocol that measures or protects it is built here. Agreement with stim's generated rotated-memory circuit is on the declared detector and observable count at distances two through eight and rounds one through four, which fixes the shape and not a mechanism-level correspondence. Execution evidence covers the distance-three patch of each family only, because the dynamic hybrid simulator draws each shot from the full output distribution and a distance-five rotated surface patch is 2**49 amplitudes per shot while a distance-five colour patch is 2**37. No decoding, no threshold, no logical-suppression, no fault-tolerance, no real-time and no hardware-feedback claim follows from a declared code, a detector layout, or a syndrome trace.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.qec.CssCode`, `flagquantum.qec.css_code_matrices`, `flagquantum.qec.CssCodeMatrices`, `flagquantum.qec.triangular_colour_code`, `flagquantum.qec.toric_code`, `flagquantum.qec.bivariate_bicycle_code`, `flagquantum.qec.qldpc_code`, `flagquantum.qec.reed_muller_code`
- **Runtime modes:** `local_statevector_dynamic_hybrid`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../examples/qec/css_code_from_matrices.py)
- **Documentation:** [guide](../../flagquantum/qec/README.md)
- **Known boundary:** A declaration route, not a code library. It admits a code whose checks and logical operators can be written as 0-or-1 rows over the data wires, which is the CSS class and nothing outside it: a mixed X-and-Z stabilizer has no row, because stating one would mean writing it as a row of each family and the pair of matrices would then describe checks that do not commute. That is a limit of the matrix route and not of the check protocol, which measures a mixed stabilizer with one ancilla and both CNOT directions; a code whose checks are all mixed is declared as a record instead, and ZxxzSurfaceCode is the first one. The matrices are Python sequences of sequences, because this module holds no array dependency and states none; a tensor block reaches the route only through the `.tolist()` the refusal names. Every invariant is checked rather than assumed: the two check families commute, each declared logical operator commutes with the opposite check family while not lying in the span of its own, the declared logical operators of a family pair up non-degenerately, the blocks agree on a width that leaves at least one logical qubit, no row acts on no data qubit, and each family declares as many operators as the width and the two ranks leave logical qubits. The distance is searched for rather than read off the representative the caller wrote down, which is what makes it a property of the code: the same Steane record reports three whether its logical operator is written at weight three or at weight seven. That search is bounded, and the bound is the caller's to accept: it tries wire subsets in increasing weight up to `distance_search_weight`, which defaults to three, and refuses when the bound is exhausted instead of reporting the best it found. The cost of the bound grows with the data-qubit count, and the route is demonstrated from eight to seventy-two data qubits rather than claimed as a distance algorithm for a large code; the seventy-two-qubit case is the published instance of the bivariate-bicycle family and its search is the one that takes measurable time, about eighteen seconds against no measurable time for the eighteen-qubit member of the same family. A code whose two distances differ is where the bound bites hardest, and reed_muller_code is the first record here whose two family distances are not equal: the punctured Reed-Muller convention it states has an X distance of seven beside a Z distance of three, so the default bound of three refuses the code, the caller must ask for a bound the search reaches, and the record then reports the smaller number as the distance and both numbers separately. Which block states which check family is a convention rather than a fact about the code, and the rule states the one the parity contract names; exchanging the two blocks is the same code with the two Pauli families renamed, which was measured before the rule was written rather than assumed. The bound is also why that route stops at width five: the least X-type operator has weight seven, so proving it means exhausting every subset of weight up to six, which is affordable over the fifteen and thirty-one points of widths four and five and not over the sixty-three and one hundred and twenty-seven of widths six and seven, where the same search would look through 75611760 and 5434287328 subsets. The rule is stated for every width at or above four and the route refuses above five by name, so the narrower reach is the route's cost rather than a claim about the family. The refusal is per family and fail-closed rather than a fallback to the lightest operator it found, which is what makes the bound a statement about the search rather than about the code. Nothing here decodes, protects a logical qubit, or states a threshold, a logical-suppression figure or a family's error rate. Two routes reach a record and they are distinguished by where the matrices come from: a caller writes them, as the torus the golden path walks through does by hand, or the route derives them, as triangular_colour_code and toric_code do for families this package declares. The second is what keeps a declaration from being copied from another framework's source, and it now covers four families: one patch, one periodic lattice, one qLDPC family, and one written on the Boolean cube rather than on a lattice or a group. A caller's own matrices reach that same derivation directly, so a code that arrives as a specification rather than as a family rule no longer has to have its logical operators written out with it. The last of those is the one whose rule names no logical operator at all, so the route derives those too, as a null space taken modulo the stabilizer span; the null space itself lives in flagquantum/qec/gf2.py rather than beside the family, because it is the same reduction over the same rows that every other question here is asked with, and the two steps built on it -- the complement of the stabilizer span and the symplectic elimination that follows it -- live in flagquantum/qec/qldpc.py, which is what the bicycle family and a caller's own matrix pair both call. Two properties of the derivation are stated rather than implied. The logical count is the matrices' rank and not their row count, so a construction that subtracted checks would report no logical qubit at all and refuse the smallest instance. And each family comes back in the order the symplectic pairing puts it, so a record's own lz[i] and lx[i] are partners rather than merely paired in some order. The derivation is held to an instance nobody here chose: over Z_6 * Z_6 with A = x^3 + y + y^2 and B = y^3 + x + x^2 the record reports [[72, 12, 6]], the parameters the literature states for that pair. tests/qec/test_bicycle_code.py keeps that instance behind a slow marker for its cost and measures the properties of the built record on the eighteen-qubit member instead, which is free. The golden path holds the two descriptions of the torus against each other on everything the edge numbering cannot change -- the qubit and check counts, the distance, the logical-operator count and the full mechanism-weight histogram of the detector error model -- because the caller's numbering and the record's are different and no attempt is made to relabel one into the other. The generic entry point has since landed as flagquantum.qec.qldpc_code, which takes an arbitrary parity-check matrix pair and derives its logical operators, so the route is no longer demonstrated only for the families this package declares. It was held to the four codes whose logical operators are declared elsewhere before it landed -- the Steane record, the torus at two sizes and the bicycle family -- and the parameters alone would not have held it, because a complement of the stabilizer span is not unique and a wrong representative of the right class reports the same count and the same distance. The test therefore requires every derived operator to differ from its declared partner by a check of its own type. One of the two properties above is only visible through this route: on the distance-three torus a derived Z-type operator spans seven data qubits while the record reports a distance of three, because the distance is searched over the code rather than read off the derivation. What remains absent is the Reichardt and Floquet families, which have neither a record nor a matrix route, and no family here states a gauge subsystem. Two refusals belong to the sibling routes rather than to this one and are inherited: a declared product that is not pure X or pure Z is refused by the memory circuit, and a model whose mechanisms flip three or more detectors is refused by the matching decoder, which is what a code whose lightest logical operator is not the lightest fault looks like from the decoder's side -- a refusal the colour code runs into deliberately, and which the belief-propagation decoder does not share.

### Subsystem-code record

Read a parity-check and gauge-operator table as a subsystem code: declare the checks, the gauge generators and the logical operators, and get back the number of protected qubits the checks and the gauge leave together, with the distance searched for under the dressed reading in which a logical operator is read modulo its own family's checks and gauge.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.qec.SubsystemCode`, `flagquantum.qec.tesseract_code`, `flagquantum.qec.tesseract_column_swap`, `flagquantum.qec.tesseract_free_cnot_pairs`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../flagquantum/qec/IMPLEMENTATION.md)
- **Documentation:** [guide](../../flagquantum/qec/IMPLEMENTATION.md)
- **Known boundary:** A declaration record, not an experiment. SubsystemCode takes the same four blocks flagquantum.qec.CssCode takes and adds the two gauge blocks, and the two additions change what the four mean rather than adding to them: the tesseract's sixteen data qubits carry ten independent check rows and two anticommuting gauge pairs, so the checks alone leave six classes and the record reports four protected qubits beside two gauge qubits, which is exactly the family's four declared logical operators. The protected count is derived from the two check ranks and the gauge block's length rather than stated, so a caller who writes the count down does not get it honoured. Every invariant is checked: the two check families commute, every gauge generator commutes with every check, no gauge generator lies in its own family's check span, the two gauge blocks pair up non-degenerately, and each logical operator commutes with the opposite checks while lying outside its own family's checks *and* gauge. The distance is the dressed one and it is searched for rather than read off the declared operator, under the same bounded distance_search_weight the matrix route uses and with the same refusal when the bound is exhausted; the tesseract reports four under both readings, and the file measures the same four when the operator is additionally required to commute with the opposite gauge generators, so the published number is not an artifact of which center the search took. That the distance is dressed rather than bare is a measured claim and not a coincidence of the tesseract, whose two readings agree: the file carries a second family, the 3x3 Bacon-Shor, where reading up to the checks alone finds a weight-two operator and the record reports three. One thing is deliberately absent. This package has no round structure, no detector model in which a gauge generator is measured and no decoder registered for a subsystem protocol, so the record builds no memory circuit, samples no noise and reports no distance in the executable sense, and the gauge-generator absence the stim-interop sweeps record is unchanged. The record is also deliberately not a flagquantum.qec.StabilizerCode, so flagquantum.qec.css_code_matrices refuses it with the protocol named instead of building matrices the gauge generators would be dropped from -- a subsystem code is a second reading of matrices this package already accepts, not a second matrix class. One family ships, the tesseract, whose gauge tables are four representatives of the gauge span modulo the checks rather than the family's raw neighbouring pairs, because a gauge qubit is a pair. The search bound is the caller's to accept. The family's free-CNOT gadget is published beside the record rather than held by a test: tesseract_column_swap derives the sixteen-wire permutation from the hypercube layout -- a wire whose lowest coordinate is clear exchanges the column above it -- and tesseract_free_cnot_pairs states the two protected pairs the permutation is held to act on as CNOT(control -> target) and nothing else, so the claim that the permutation implements two free logical CNOTs joins two independently written facts instead of restating one. The derivation is not a claim about how the code looks: the tuple it returns was measured against the one the framework this package replaces publishes for the same family, wire for wire, on the same protected order. What the pair of functions does not do is compile the gadget, and the action they state is stated on the record's own protected order rather than against a port-named encoding. Nothing here is differentiable, distributed or accelerator-backed, and no threshold or logical-suppression claim is made.

Construction derives a signature rather than asserting one. The round-zero coin toss of an X-type ancilla -- which is what made the executed route demand agreement on the flip set rather than on the register, and which is why a code with an X-type check was once refused -- is not a case the derivation has to handle at all. The modelled rotated-surface distance is therefore 3 or 5 or 7 as the caller asks, and no distance is refused for its width. The route this replaced forced each location through an execution and read the same layouts off the result. It survives as _forced_signature, which still refuses a mechanism whose flip set is not deterministic across two trajectories and whose source does not carry the line the mechanism is injected at, and the suite holds the derivation against it rather than trusting it: the comparison is location by location, over every mechanism of a repetition code, a Steane code and a rotated surface patch, over every fault family, and in both readout frames. That executed route is bounded where the derivation is not -- a distance-4 patch is 31 wires and 2**31 amplitudes, and a distance-5 patch fails on the allocator outright -- and a test asserts that the distance-7 patch builds, which is what fails if the derivation is replaced by an execution again. What the derivation gives up is the executed route's guard against a hand-built record whose layouts misdescribe the program it stores. Three such shapes are still refused with the reason the injection engine stated -- a source missing the round loop anchor or a check's measurement anchor, and a detector whose syndrome reference names an ancilla no check owns -- but a layout that is merely wrong about a mechanism the program does contain is now read as the record states it, and nothing inside construction holds it; only the test-level oracle does. That is the narrowest honest statement of the route, and it is recorded rather than left silent. The matrix route is unbounded in the same way and for the same reason: reading a matrix support costs one pass over its nonzero entries per round. A second construction route reads a code-capacity experiment rather than a memory circuit. DetectorErrorModel.from_code_matrices takes a CssCodeMatrices record -- the four CSS blocks hz, hx, lz and lx -- and derives every mechanism combinatorially, and css_code_matrices lifts a code record into that record, refusing a logical observable that is neither pure X nor pure Z rather than half-reading a CSS code. Its geometry is not the memory circuit's and the difference is pinned rather than glossed: a fault in round r reaches the detector band of round r and of round r + 1, the final round has no band after it, and there is no terminal data readout, so the detector count is num_rounds * num_checks where a memory circuit gains one terminal detector per Z-type check. Both geometries are asserted against their own stim transcription, and the same suite asserts that the two counts differ. The matrix route is compared to stim one readout basis at a time, because lz and lx anti-commute and no one state has both as a deterministic value: the reference experiment is run twice against the model restricted to the matching basis, and each run's observable rows are the ones the Pauli character of that fault family predicts. A fault that is still in the data at the end of the run is still seen by the logical readout, so a physical fault spans one detector band while the model gives it two; that single divergence is pinned as the exact relation between the two mechanism sets rather than as a tolerance. The fault family is the three single-qubit Pauli faults plus a check's syndrome bit flipped at readout, so an X fault flips Z-type checks, a Z fault flips X-type checks and a Y fault flips both, and the X detector band and the lx observable rows exist on the matrix route. The rate record is no longer what is narrower than upstream's. PhenomenologicalNoise states upstream CssNoise's four families as four scalars -- data_flip, phase_flip, both_flip and measurement_flip, which are its px, pz, py and pm -- and the same four per element as data_flip_per_qubit, phase_flip_per_qubit, both_flip_per_qubit and measurement_flip_per_check, which are its px_per_qubit, pz_per_qubit, py_per_qubit and pm_per_check. A stated vector replaces its scalar wholesale rather than mixing with it, a vector that does not name every data qubit or every check is refused naming both counts instead of being partially applied, and an element whose effective rate is zero enumerates no mechanism at all, so a quiet location between two noisy ones is expressible and costs nothing to sample. The per-qubit vectors are indexed in the code's own data_wires order, which is the column order of every matrix, and the per-check vector by matrix row with the Z-type checks first; a code may declare its checks in any other order -- the rotated surface code interleaves the two types -- so the two orders are related by one named translation that all three readers share. What remains different from upstream is the carrier rather than the rates: upstream folds the record into the argument its matrix entry point takes, so the vectors are validated against matrices that arrive with it, where here the record is a standalone frozen dataclass and its vectors are resolved against a count the reader supplies. The sampler reads the two families the engine has a channel for, so the phase and Y data rates reach a model and not a sampled record. A matrix that is not binary, is not two-dimensional, or is not indexed by the same data qubits as another non-empty block is refused rather than coerced. The matrix route is graphlike only while it stays inside one round; at two rounds the middle data wire of the distance-3 repetition code flips the same check in both bands, which is a four-detector mechanism, and the matching decoder refuses it as a hyperedge. The model is built on the memory circuit without in-circuit feedback, because it describes the noise-to-detection mapping a decoder inverts, so the frozen profile's compiled-feedback path is unmodelled. Detector rates are cross-checked against rates sampled from the circuit simulator, and the two no longer share the signature computation: construction derives a mechanism's flip set from the layouts while the cross-check's oracle injects the mechanism into the stored program and executes it. tests/qec/test_dem_from_memory_circuit.py compares the two location by location over every mechanism of three codes and every fault family, and it is also where the distance-7 patch is asserted to build. tests/qec/test_dem_signatures.py pins the oracle's own readings against absolute detector indices looked up in the layout, so the oracle is not checked against the route it guards. An independent check does exist and runs against the optional stim distribution: the memory circuit is transcribed into a stim circuit and stim's own error analysis builds the model, which agrees with this one on shape, mechanism count and detector marginals at distance 2 and 3. That check shares nothing but the circuit's gate sequence and the noise model. The text reader accepts everything stim 1.16.0 wrote in a 240-model developer-time sweep except a repeat block, a # comment, a declaration that skips an index, and a malformed line; str(detector_error_model.flattened()) is a complete route around the repeat refusal. A line's ^ separators are read the way stim means them -- the signature is the symmetric difference of the targets, so a detector named twice cancels and the groups are not retained -- and the decomposition the separators suggest is available under upstream's own flag name as from_stim_text(text, use_decomp_suggestions=True), which returns one mechanism per component at the probability the line states and turns 536 mechanisms into 1042 on a distance-5, two-round rotated surface code. That second reading is a different distribution from the line rather than an equivalent statement of it, and it is measurably so: against stim's own sampler on the same text the default reading's worst marginal misses by 0.0016, inside the 0.004 tolerance, while the expanded reading misses the observable marginals by 0.048, twelve times outside it, which is what makes the tolerance evidence rather than decoration. A component that cancels to nothing is refused by the expanded reading alone, with the default reading named as the route that states the line. The text writer is exact on this side and stim's width is the platform's: stim prints at numeric_limits<long double>::digits10 + 1, so nineteen significant digits where long double is the x86 80-bit extended type (the Linux CI runners, where a reprint returned every swept probability unchanged) and sixteen where it is a double (arm64 macOS, where about a quarter of the same sample came back changed); seventeen digits name a double uniquely, so a round trip through stim must compare against a re-read of the text rather than against the in-memory model exactly where the width is the narrower one, and the drift there is bounded by one part in 10**15 and measured at 5.4e-16 worst case, while tests/qec/test_dem_stim_text_precision.py reads the width off stim's own output and pins the digit count, the direction of the loss and the bound against it. A CodeCheck states one ancilla and one CNOT direction fixed by the check's type, so a code with both check types is expressible while a mixed X-and-Z stabilizer is refused; the detector grammar is therefore z_checks * (rounds + 1) + x_checks * (rounds - 1) rather than one detector per check per round, and a code family needing a second ancilla per stabilizer still requires that record to grow first. dem_sampling reports a DEM-sampled rate and is labelled as one wherever it is reported; no decoder, no threshold, no logical-suppression, no real-time or hardware-feedback, and no performance claim follows from a detector error model or from any rate it reports. DemSample carries tensors and is deliberately unhashable. The merge is a stated operation and not only a construction step: DemMergeRule names its two rules for what they compute, INDEPENDENT_PARITY being the probability that an odd number of a duplicated group fires and CLAMPED_LINEAR_SUM the sum of the group clamped at one, mechanisms_are_unique and require_unique_mechanisms are the predicate and the refusal, and the parity rule is exact rather than approximate because a detector's rate is a product of 1 - 2p factors over the mechanisms touching it, so a group's combined prior is the single p whose factor is that product and regrouping the factors cannot change any detector or observable rate; the sum rule does not preserve them and is offered only for a caller who means it. A model may also state that mechanisms are alternatives rather than independent, which is the one statement its parity matrices cannot carry, because two columns of a parity matrix are independent by construction: DemError.error_id is an optional non-negative label, the mechanisms sharing one are mutually exclusive, and DetectorErrorModel.error_ids projects upstream's optional vector back out, None when no mechanism states an id, which is upstream's nullopt and the state stim's text always describes. Exclusivity is given a distribution rather than left as a bare flag: the members of a group are disjoint pieces of one shot and each keeps the probability it states, the left-over mass is the group firing none of them, and a group whose probabilities sum above one is refused rather than renormalized, because renormalizing would change every rate the caller read; a group summing to exactly one is admitted, and a lone id excludes nothing and behaves as if it were unstated. The model's own arithmetic honours the groups, so the marginal rate of a target sums the group members that touch it instead of composing them by parity -- 0.26 for two independent mechanisms of 0.1 and 0.2 against 0.30 for the same two stated as alternatives -- and sampling draws one uniform per group and lets at most one member fire, so a model with no ids, which is every model the construction routes here produce, keeps the arithmetic and the draws it had before the field existed. The statement is not transcribable, and the operations that would silently drop it refuse instead: to_stim_text names the ids it would lose rather than printing an independent model under the same probabilities, and merge_duplicate_mechanisms names them because either rule combines mechanisms by assuming independence and would invent a shot in which two alternatives both fired. What remains absent is an operation that folds a group under its exclusivity rather than merging by independence, which is the gap the canonicalize field row records. A decoder is handed both halves of what it needs, not only the model. detector_context_from_memory_circuit builds the model once and returns a DecoderContext whose full_component, x_component and z_component each return a DecoderInputs -- the model together with both maps -- and whose num_measurements states the width those maps index. A MeasurementMap is one row per detector or observable holding the measurements whose parity it is: dense() projects to the (rows, measurements) orientation upstream stores as D and O, and flattened() to the -1-terminated sparse form a realtime decoder configuration takes, the terminator being what keeps a row that reads nothing visible to a sparse reader. The map is closed rather than conventional -- a row is sorted because a parity is a set, it may not name one measurement twice because two reads of one measurement cancel, and an index outside the buffer is refused. The basis split is a projection of the model as built rather than a second construction: a detector belongs to the check whose ancilla it reads, so the Z component carries the terminal detectors and the union is the model itself, with no boundary-aware variant needed because the layout states its own boundary detectors. Two refusals keep the projection a reading rather than a rewrite: a component of a model that states error ids is refused, because projecting a group of alternatives would either drop the correlation or merge two of its members, and a component whose basis has no detector is refused rather than returned empty. The numbering the maps use is derived from the circuit's declaration and asserted equal to the numbering the sampler derives from the lowered program, so the two readings of one record convention are pinned to each other by measurement rather than by a shared constant. The context does not execute the circuit, costs one construction and no simulation, and carries no rates vector, no canonicalization and no chunk or seam helper. The other direction is stated beside construction rather than folded into it: dem_circuit.py writes a model as the detector-level realization it already is -- one wire per detector, one per observable, one Pauli-frame channel per fault -- and reads it back exactly, error ids included, because a frame's operators say which targets a fault flips and its declared masses say how often, so no mass is recovered by squaring a square root. What it returns is not the circuit the model was built from and cannot be, because a detector error model states which detector parities a fault flips and never which measurements compose a detector, so the syndrome-extraction circuit, its gate sequence, its depth and its ancilla layout are outside it and two different memory experiments of one distance under one noise record define the same model; the detector count is the caller's to state, and a mechanism at probability zero is refused rather than dropped. ### Minimum-weight matching decoder over a detector error model

Turn the detector error model of a memory circuit into a weighted graph and decode a syndrome exactly by minimum-weight matching, reporting the mechanisms selected and the logical observables they flip.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.qec.DecodingGraph`, `flagquantum.qec.DecodingGraphEdge`, `flagquantum.qec.MinimumWeightMatchingDecoder`, `flagquantum.qec.MatchingDecodeResult`, `flagquantum.qec.PyMatchingDecoder`, `flagquantum.qec.get_decoder`, `flagquantum.qec.register_decoder`, `flagquantum.qec.decoder_names`, `flagquantum.qec.DetectorErrorModelDecoder`, `flagquantum.qec.AUTHORITY_NAME`, `flagquantum.qec.CROSS_CHECK_NAME`, `flagquantum.qec.SLIDING_WINDOW_NAME`, `flagquantum.qec.SlidingWindowMatchingDecoder`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../flagquantum/qec/IMPLEMENTATION.md)
- **Documentation:** [guide](../../flagquantum/qec/IMPLEMENTATION.md)
- **Known boundary:** One decoder, for graphlike detector error models only, on one detector error model at a time, with no threshold, no logical-suppression, no real-time, and no performance claim. A decoding graph is built from the model's mechanisms and nothing else: a mechanism becomes an edge whose weight is log((1 - p) / p), a mechanism flipping one detector becomes an edge to a boundary node one past the last detector, a mechanism flipping three or more detectors is a hyperedge and is refused with a stated reason rather than projected onto a pair, a mechanism of probability zero contributes no edge because its weight would be infinite, and two mechanisms that share a detector pair but disagree on their observable labels stay two edges because merging them would either lose a logical flip or invent a weight neither mechanism has. Two mechanisms that agree on both are the different case and are refused: one fault stated twice would become two parallel edges and the matcher would charge the cheaper of them, log 4 for mechanisms of 0.1 and 0.2 where the fault's own combined parity 0.26 has weight log(0.74 / 0.26), so the matcher would prefer a longer chain of other mechanisms over the mechanism that actually fired. The decoder therefore requires a unique signature before it builds a graph, names both mechanisms and the merge that resolves the duplicate, and leaves the graph's parallel edges intact so the refusal is a decoder decision and not a representation one. A model that states two mechanisms are alternatives is refused for the neighbouring reason: one weight per mechanism is the weight of a fault that fires alone, while a group of alternatives is one fault whose weight is the negative log-likelihood of the group, so the graph refuses such a model and names the groups rather than weighing each member as though the others could fire with it. Whatever the model states is what the graph holds, so the decoder inherits every scope limit of the detector error model it consumes. The width of the patch is not one of them any more, because the construction route derives a signature from the circuit's layouts rather than forcing one through an execution; what bounds this decoder is its own enumeration, and the budget below is where that shows. The matcher is exact and self-implemented: it searches each defective detector for the cheapest chain of mechanisms to every other detector and to the boundary, and then enumerates the ways to pair the defects and to route any number of them to the boundary, which is a minimum-weight perfect matching on the metric closure. The boundary is a sink rather than a waypoint, which is what makes a syndrome's parity irrelevant, and chains may pass through defective detectors because edges two chains share cancel in the symmetric difference. Because the pairing is enumerated, the decoder accepts at most twenty detection events per syndrome by default and refuses a larger syndrome as a capability boundary rather than returning a pairing that only looks cheapest; the budget is a constructor argument because the cost is in that enumeration, so a distance-three patch at ordinary noise decodes while a much larger syndrome is declined. Detectors that no chain of mechanisms connects are refused with a stated reason rather than answered partially. The prediction is the exclusive-or of the selected mechanisms' observable labels, so it is a decision about which cheapest explanation the decoder adopts and not an estimate of the probability that the observable flipped, and it is not calibrated: two mechanisms that share a detector pair and disagree on their label are indistinguishable from the syndrome alone, so the decoder cannot always recover the more likely value. Its failure rate is therefore at or above the optimal decoder's on every model and strictly above it once rounds exceed one. A single-round repetition model has no such pair, and there the matcher reaches the exhaustive optimum exactly, which is the only optimality claim made here. The sliding window is no longer one of the absences and it is not a second decoder either: flagquantum.qec.SlidingWindowMatchingDecoder decides a syndrome a band of detectors at a time and calls this matcher on each window, so the budget above bounds a window's syndrome rather than a whole history's, which is what lets a long-lived memory experiment be decoded at all. Its own limits are stated rather than folded in here: it is exact only in the limit of one window over the whole graph, its default band is the model's measured widest mechanism and its default window is three bands, a window narrower than a band plus that span is refused by name, the observables it predicts can differ from this matcher's at a narrow width, and no threshold or logical error rate is estimated from a windowed decode. It is recorded inside this entry rather than as an entry of its own, because it is this decoder read through a window and not a numerical core beside it: the graph, the weights, the mechanism set and the refusal set are this entry's, and what the window adds is an argument about how much of a history one call reads at once. Absent here: a union-find or belief-finding decoder, and the plugin boundary upstream ships, which remains a precedent rather than a protocol. The hyperedge scope this entry does not cover is covered by a decoder that is not this one and is recorded separately, so it is a gap against the baseline and not an unowned one: the capability qec_belief_propagation_osd_decoder states the belief-propagation decoder with ordered statistics, flagquantum.qec.BeliefPropagationOsdDecoder, that answers a three-detector mechanism this graphlike scope refuses, and that decoder stays outside the name-keyed registry because a model with such a mechanism has no pair-graph for the registry's protocol to promise. Batching, streaming, and a per-detector error-rate vector are also absent, and the decoder is not connected to the stim sampling path. The matrix route that DetectorErrorModel.from_code_matrices provides is inside this decoder's graphlike domain only while it stays inside one round: at two rounds the middle data wire of the distance-3 repetition code flips the same check in both detector bands, which is a four-detector mechanism, and the decoder refuses it as a hyperedge rather than projecting it onto a pair. The observable prediction has no consumer yet: no logical-error-rate estimator, no threshold scan, and no integration with the memory-experiment result records. The result record is deliberately not the repetition-code DecodeResult, whose correction carries a wire in {0, 1, 2} and an X basis only and therefore cannot express a surface-code correction. A second decoder exists behind the pymatching extra and is a cross-check rather than the authority: flagquantum.qec.adapters translates the same decoding graph, reports the same two records, and is imported lazily, so the core install and the decoder neither need nor load it. What the comparison establishes is stated narrowly, because the two instruments are not equal: PyMatching reports 3.9020747171643912 for a mechanism this package states as 3.9020746947749574, so the graph it minimizes over is not exactly this one and two explanations closer than that difference can be ordered differently on the two sides. The two decoders are therefore compared on the cheapest weight of every syndrome with a tolerance of one single-precision rounding per selected mechanism, on the observables wherever the cheapest explanation is unique, and on their refusals as the same set; a tie is uncomparable rather than evidence against either implementation, and one tie of the distance-three repetition code is pinned by hand so that the clause is a demonstrated fact rather than a place a disagreement could hide. The translation refuses two graphs instead of approximating them, and both are graphs the matcher itself answers: a detector pair carrying two mechanisms, which PyMatching's independent merge strategy would collapse and thereby lose a logical-label difference, and a detector that no mechanism flips, which PyMatching cannot represent because it infers its detector count from its edges. The cross-check's domain is therefore narrower than the authority's and never the reverse. The matcher is checked against brute force on syndromes small enough to enumerate, against the exhaustive enumeration of a model's own mechanism distribution, and against that second decoder over the same graph, so its correctness rests on the detector error model all three read and on the authority of no external decoder. A name reaches a decoder through flagquantum.qec.get_decoder, and the name is not a promise about the implementation: the registry returns the class a name is registered against and never prefers one because it is available, so the authority is returned for its own name wherever the optional extra happens to be installed. The registry is narrower than the CUDA-Q QEC decoder surface it is aligned to. Its source argument takes the three carriers a caller can hold a model in -- the detector error model, stim's text for one, and the decoding graph the model defines -- and not a parity-check matrix, because lifting a matrix would also mean choosing the noise model and round count that DetectorErrorModel.from_code_matrices reads rather than defaults. It holds the detector-error-model family alone: the repetition-code decoders take an ordered syndrome history rather than detection events, so registering both under one name space would make a name mean one of two things, and they stay directly constructed. It fails closed rather than falling back: an unregistered name raises and lists the registered names, a class missing decode or from_detector_error_model is refused while the registering module is imported rather than at the first caller, a source that is not one of the three carriers is refused by type, and a second registration of one name is refused unless the caller asks to replace it. The optional implementation is registered whether or not PyMatching is installed, so its name is part of this package's surface rather than the extra's and asking for it without the extra raises the error naming the extra. The registry selects among decoders; it does not add one, so the hyperedge model that belief propagation with ordered statistics decoding now answers is reached by constructing that decoder directly rather than by name; the plugin boundary upstream ships remains a precedent rather than a protocol here.

### Belief-propagation decoder with ordered statistics over a detector error model

Decode a syndrome a minimum-weight matcher refuses, by iterating min-sum messages over the model's mechanisms and then solving the syndrome over the most error-prone independent ones, so a mechanism flipping three or more detectors is answered rather than declined.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.qec.BeliefPropagationOsdDecoder`, `flagquantum.qec.BeliefPropagationOsdDecodeResult`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../flagquantum/qec/IMPLEMENTATION.md)
- **Documentation:** [guide](../../flagquantum/qec/IMPLEMENTATION.md)
- **Known boundary:** One decoder, in-process, over one detector error model at a time, with no batching, no streaming, no threshold, no logical-error-rate estimator, and no performance claim. The colour code was the first shipped family whose decoding evidence is this route rather than the matcher's, because its faces carry a single fault into three detectors and the matcher refuses the model: tests/qec/test_colour_memory_execution.py decodes every single fault of the executed distance-three patch and every syndrome the distance-five model samples, and asserts of each that the correction reproduces the syndrome it was given. The torus is the second, and it is the family where this route is measured as a rate and not as reproduction alone: tests/qec/test_toric_memory_execution.py takes the two-round declared model of the distance-three torus, whose eight weight-four mechanisms are exactly what moves it out of the matching decoder's reach, and asks every one of three hundred draws -- the empty syndrome included, which must be answered by selecting no mechanism -- for a set of mechanisms that reproduces it and for the observables they flip. At a one-percent fault rate the decoded logical rate is 0.0033 and 0.0100 against the model's exact raw rates of 0.1000 and 0.0933, and the margin that row asserts is a factor of four. The same measurement at the five-percent rate the file's other profile rows use is 0.2667 against 0.3588, a ratio of 1.34, and that number is recorded here rather than asserted into a claim: order-zero post-processing leaves the free mechanism positions at zero, so at that rate this decoder is a route to an answer and not a suppressed logical-error rate. The same file also records where the exact matcher's own budget bites -- at six rounds and two percent a sampled syndrome carries twenty-two detectors against its default twenty -- and that the windowed matcher refuses strictly fewer of those same draws while the hyperedge decoder and the PyMatching-backed name refuse none of them. It is a decoder and not an optimal one: belief propagation is an estimate, and the ordered-statistics pass holds every mechanism outside the elected information set at zero, so an answer reproduces the syndrome and need not be its most likely explanation. The exact claims are the measured ones. On the one-round Steane model the decoder reaches the least weight and the most likely observable for all 64 syndromes. On the one-round rotated surface code it carries more weight than the least-weight explanation on five of the 256 syndromes, by 0.6904 on two and 2.9444 on three, and differs from the most likely observable on three of those five, so the whole of its gap to an optimal decoder on that model is those five syndromes and not a property of the code. The iteration is min-sum with a caller-set damping factor, runs a caller-set number of passes, and reports whether it converged rather than looping until it does. The magnitude of a check message is capped, so a detector only one mechanism can flip forces that mechanism without producing an infinite message, and a mechanism whose stated probability is one or zero is floored before its log-odds ratio is taken so that the ratio stays finite. The decoder is reached through the name-keyed registry as get_decoder("belief_propagation_osd", model), and getting it named is why that registry states two protocols instead of one. Its DetectorErrorModelDecoder states what every registered name promises -- decode, returning the observables the correction flips -- and the pair graph moved to GraphlikeDetectorErrorModelDecoder, because a model carrying a three-detector mechanism has no pair-graph at all: DecodingGraph.from_detector_error_model refuses it as a hyperedge. The three matching names satisfy the graphlike protocol and this one does not, and a DecodingGraph handed to this name is refused with that reason rather than failing inside the constructor. The module imports torch and the standard library and nothing else, it is not wired to the stim sampling path, it reports the observables a mechanism set flips as a prediction rather than as a probability, and it is not calibrated.

### Sampled detection events from a memory circuit

Sample a memory experiment's detection events and observable flips from the circuit itself under phenomenological noise, so a decoding claim has a route that does not depend on the statevector ceiling.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.qec.sample_memory_circuit`, `flagquantum.simulation.stabilizer.sample_noisy_measurements`
- **Runtime modes:** `stabilizer`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_process`
- **Start:** [quick example](../../flagquantum/qec/README.md)
- **Documentation:** [guide](../../flagquantum/qec/README.md)
- **Known boundary:** One experiment shape and one noise grammar. The circuit must be a MemoryCircuit, so the sampler is reachable from a code record and not from an arbitrary annotated circuit; the noise must be a PhenomenologicalNoise, so a data fault at a round boundary and a measurement flip at a check's readout are the only two locations that exist, and each of those two locations can be given its own rate through the record's per-qubit and per-check vectors, so a quiet wire between two noisy ones is sampled as stated. All three data fault families are placed, and they are placed as three locations at one instruction rather than one location named three times: an X fault, a Z fault and a Y fault are three Pauli channels, and the Y fault is one channel whose single non-identity branch carries the Y operator rather than an X fault placed beside a Z fault, because two independent faults fire independently and that is a different mechanism -- the Y replay is exact against the model per family and per wire, the marginal rates agree for both the one-channel and the two-channel reading, and the pair rates are what separate them, so a regression that merged the three would be reported by a comparison the record itself supplies. The Z fault propagating to the X-type checks the way the X fault propagates to the Z-type ones is a property of the circuit the sampler executes and not of the placement, so a code that declares one check type reports no detection event for the other basis's fault and the model agrees. What has no location to be placed at is a channel placed after a named gate, and a depolarizing or damping channel, and the per-check vector is resolved against the code's check count before any placement is derived, so a profile that names the wrong number of checks is refused rather than silently read against the wrong one. Placement is derived from the lowered program rather than written into the experiment, because the bounded hybrid capture refuses a channel call in the source; the derivation requires the program to lower to `rounds` identical round blocks that measure every check once in the code's declared check order, and refuses a program that does not, so an experiment whose round structure differs is declined rather than sampled. The sampler executes on the stabilizer engine, so it requires the optional `stim` distribution and inherits the engine's opcode set: exactly the thirteen Clifford opcodes, with a non-Clifford gate refused by name. It shares the code record's Z-memory limit, so an X-type logical observable has no route here. Sampling is not differentiable and returns no gradients. The result is a DemSample like the model's own sampler returns, and the two are deliberately different code paths: the model derives a mechanism's signature from the source while this sampler derives its instruction position from the lowered program, and the tests pin the two to each other rather than having one call the other. A seed reproduces a run on one engine version and one machine instruction set; it does not pin a bit pattern across machines or engine versions. No threshold, no logical-suppression, no fault-tolerance, no real-time and no performance claim follows. The rate this sampler reports is a circuit-sampled rate, and the model's own sampler reports a DEM-sampled one; neither may be reported as the other. What the route produces is checked on the axis a decoding claim needs: tests/benchmark_contract/test_qec_memory_logical_error_rate.py decodes the logical error rate of a repetition code and a rotated surface patch at distances 3, 5 and 7 at three physical rates, on this sampler's detection events against a stim transcription of the same circuit, with one decoding algorithm on both sides and a five-standard-error tolerance asserting the difference of two independently sampled rates. The rate falls from distance 3 to 5 to 7 in all twelve configurations on both sides, and that monotonicity is the whole claim: three distances at three rates estimate no threshold and support no logical-suppression, fault-tolerance or performance claim. The comparison is on aggregate rates rather than on per-shot labels, because both models carry mechanisms of equal weight and a minimum-weight matcher is then free to name different observables for one syndrome at the same weight -- measured at distance three as 38 and 91 disagreeing shots in twenty thousand on the repetition code and 46 in five thousand on the surface patch, with the weight itself agreeing on every shot. The in-tree matcher is not on that path: it enumerates the pairings of a syndrome's defective detectors and refuses more than twenty of them outright, so the reference decoder decodes both sides, and that ceiling is an owned gap rather than a property of this route.

A model that declares a readout rule is refused rather than measured without it, because classical readout confusion is applied after measurement and is not part of rho: extrapolating a curve that omits it would return a state-preparation estimate under the name of a measured one. Readout-error mitigation is a separate unit beside this one rather than a mode of it: flagquantum.algorithms.plan_readout_mitigation inverts a declared classical confusion on a measured vector, after measurement, which is the other side of the same boundary. Probabilistic error cancellation is provided beside it by flagquantum.algorithms.run_pec, which inverts a declared Pauli channel exactly rather than measuring it at several error strengths, and Clifford data regression is provided beside it by flagquantum.algorithms.run_cdr, which fits the noise's effect on near-Clifford training circuits, and gate and circuit folding is provided beside it by flagquantum.algorithms.fold_program and this unit's own fold argument, which lengthen the program by an exact identity so that the noise its instructions carry runs more times. That third alternative is a different unit of scale rather than another scaling: a fold reports the length ratio it realized rather than a channel parameter, the realized ratio is the abscissa this fit is given rather than the requested factor, and a call naming both a fold and a scaling callable is refused because the product of a length ratio and a channel parameter names neither. A fold needs no noise model at all, so a folded run is admitted on a program whose channels cannot be scaled; what it assumes instead is that repeating an instruction repeats that instruction's error and changes no other instruction's error, and what it does not supply is any estimate of the noise it amplified. The method's one assumption is that the measured curve is a polynomial of degree at most the fit order in the scale factor; nothing checks it and it is not checkable from the measurements alone. The diagnostic that exposes a violated assumption is the largest absolute residual the fit left. At one cx gate with depolarizing noise at 0.05, the four-point curve at scale factors 1, 3, 5 and 7 leaves 1.8e-2 at degree one and 4.2e-9 at degree two, while a coherent over-rotation over the same scale factors leaves 8.9e-2 at degree one and 2.9e-2 at degree two and its estimate stays 1.1e-1 away from the noiseless value, so a non-polynomial family is visible in the residual rather than silently extrapolated. A square fit's residual is zero by construction and is therefore not evidence, which the record enforces by reporting max_residual as absent when no degree of freedom is left rather than as an arithmetic zero. The observable must be a single number, so the circuit's batch size is one, and the channel parameters keep the runtime's precision, so against the analytic value 1.0 a single-precision run recovers it to 1.3e-7 where a double-precision run reaches 3.0e-9; the exactly simulated noiseless read that a comparison is usually taken against is itself 6.0e-8 away from that analytic value at the default precision, so a distance measured against it is dominated by that offset rather than by the extrapolation's error, and every distance recorded here names the precision and the reference it is measured from. Demonstration scale: two-qubit circuits on the CPU density-matrix path, with at most seven scale factors and a fitted degree in the low single digits. No performance, scaling, hardware or fault-tolerance claim follows from it.

### Probabilistic error cancellation over a declared Pauli channel

Invert a noise channel the model declares exactly, by decomposing its inverse into a signed combination of Pauli words read off the channel's Pauli transfer matrix, and report the mitigated estimate beside the sampling overhead that combination implies.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.pec`, `flagquantum.algorithms.run_pec`, `flagquantum.algorithms.pauli_twirl_decomposition`
- **Runtime modes:** `density_matrix`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../examples/algorithms/pec.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** Probabilistic error cancellation whose premise is the declared noise model and only that model. The unit inverts the channel the model declares, at the location the model declares it: an error the model does not carry -- a miscalibrated gate, leakage, drift between the declaration and the run -- survives the inversion untouched, so a mitigated value close to the ideal is a statement about the model before it is a statement about a device. The decomposition is exact only for a channel whose Pauli transfer matrix is diagonal, which is what makes it a Pauli channel, and only while no transfer eigenvalue reaches zero, which is what makes the inverse exist at all. Both boundaries are checked at 1e-6 and refused by name rather than approximated, each refusal quoting the magnitude it measured: bit_flip, phase_flip, depolarizing, two_qubit_depolarizing and phase_damping are admitted at the probabilities tested, while amplitude_damping (1.000e-01 off-diagonal), coherent_overrotation (1.987e-01), reset_error (5.000e-02) and thermal_relaxation (1.000e+00) are refused, and bit_flip at one half is refused for a vanishing eigenvalue at Y rather than for being outside the family. The tolerance sits two orders above the complex64 floor a single-precision channel is measured at and five below the smallest refusal recorded here. The estimate is a quasi-probability average: it is not a physical density matrix and it can be non-positive, which is why the unit returns a value rather than a state. It carries no confidence interval, and sampling_overhead is gamma squared -- the shot cost a sampled implementation of the same combination would pay, because every signed weight carries its sign into the variance -- rather than a measurement of this path, which evaluates each term exactly and consumes no shot. gamma is at least one, equals one only for a channel that is itself a Pauli conjugation, and composes multiplicatively over locations, so the price of a model is the product of the prices of its sites. The cost is bounded: a combination needing more than 1024 exact programs is refused with the count it needed, which is four terms per single-qubit noise location and sixteen per two-qubit one. A model that declares a readout rule is refused rather than measured, because the observable is read as Tr(O rho) before measurement and classical readout confusion is not part of rho; mitigating readout is a separate unit beside this one, flagquantum.algorithms.plan_readout_mitigation, which inverts a declared confusion on a measured vector rather than a channel on a state. A circuit that declares its own input state is refused, because the unit re-executes the program from its IR once per term and a program built from an IR begins at the all-zero state. The circuit's batch size must be one, since one expectation is read per term. A noise model that puts no channel in the program is refused, because an identity model's mitigation is the unmitigated value under another name. Measured on h(0); cx(0, 1) with the observable zz(0, 1) and bit_flip at 0.1 on the cx: the two-location composite reads 0.639999995231628 unmitigated and 0.999999999999999 mitigated in complex128, at gamma 1.562500011642 over 16 terms and 17 exact programs, and the same run at the runtime's default precision reaches 0.999999866503455 from an unmitigated 0.639999806880951, so the floor the method leaves is the precision the channel was declared in. The one-location read of the same program is 0.799999997019768 unmitigated and 1.000000000000000 mitigated at gamma 1.250000004657 over four terms, and the two-location gamma is its square. Demonstration scale: two-wire circuits on the CPU density-matrix path, at most five noise locations. No performance, scaling, hardware or fault-tolerance claim follows from it, and no variance reduction is claimed.

### Clifford data regression over near-Clifford training circuits

Fit the affine relation between what a circuit should give and what the noise makes it give, on Clifford training circuits built by snapping each rotation of the target to its nearest quarter turn, then apply that relation to the target's own noisy expectation.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.cdr`, `flagquantum.algorithms.run_cdr`, `flagquantum.algorithms.clifford_variants`
- **Runtime modes:** `density_matrix`
- **Hardware:** `cpu`
- **Gradient support:** `unsupported`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../examples/algorithms/cdr.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** Clifford data regression whose training set is a rewrite, not a device run, and whose premise is the affine relation and only that relation. The ideal values are read from exact density simulation of each training circuit rather than from the stabilizer representation, so Clifford membership is enforced -- every training circuit is accepted by require_clifford_program before it is measured -- but never exploited, and no simulation-cost, capacity or scaling claim follows from the fact that the training circuits are Clifford. Nothing here is cheaper than the target it corrects. The method's one assumption is that the ideal expectation is affine in the noisy one over the region the training circuits span; nothing checks it and it is not checkable from the measurements alone. The diagnostic that exposes a violated premise is the largest absolute residual the fit left, and a two-point fit's residual is reported as absent rather than as an arithmetic zero, because two points determine a line and the zero would be an arithmetic identity presented as a check. The estimate carries no error bound and no confidence interval, and no improvement over the unmitigated value is guaranteed: the residual is the only warning. Only the five single-wire theta rotations are snappable -- phase, rx, ry, rz and u1 -- and each is rewritten exactly on the quarter-turn grid, to 1.8e-16 over all twenty entries in complex128, up to a single global phase that leaves the program's density matrix unchanged; a program containing no such rotation is refused by name rather than trained on itself, and cphase, crx, cry, crz, rxx, ryy, rzz, u2 and u3 have no named-Clifford word at all, so a program built from them is refused by the stabilizer engine rather than snapped approximately. A rotation whose angle is an unbound parameter has no nearest turn and is refused. Residue zero rewrites to the empty word, so a rotation already on the grid is dropped rather than emitted as an identity. A noise model keys its channels on gate names, so a model that names an operation the rewrite removes is refused, because every training point would then be measured under less noise than the target and the line would fit a difference the rewrite created; a caller who needs such a model supplies the training circuits explicitly and owns that claim. A model that declares a readout rule is refused for the same reason the extrapolation and cancellation units refuse one: the estimate is Tr(O rho) and classical readout confusion is applied after measurement. Readout-error mitigation is a separate unit beside this one, flagquantum.algorithms.plan_readout_mitigation, which corrects a measured distribution rather than fitting a value that was never read out through a confusion. A program that declares a measurement or observable request is refused too, because this unit reads Tr(O rho) from the state and consumes no request, and returning an estimate while a declared request stayed unused would report a measurement that never happened. The training set is capped at 64 circuits, which is 128 exact simulations, and a caller-supplied set is capped at the same number. A training set whose noisy values do not separate is refused rather than fitted on rounding, at a declared floor of 1e-9 of the span rather than at a value reached by tuning. Measured: for h(0); ry(0, 0.7); ry(1, 0.4); cx(0, 1) observed as Z0 + X1, with two-qubit depolarizing noise at 0.06 on the cx and one-qubit depolarizing noise at 0.03 on the h, the three training points read ideal 0.0, -1.0, 1.0 against noisy 0.0, -0.898560, 0.936000, the fit reads slope 1.090028330 and intercept -1.360e-02 with a residual of 1.360355e-02 over one degree of freedom, and the target's exact value -0.254799345 is read as -0.214372678 unmitigated and -0.247275845 mitigated, so the correction closes 4.043e-02 of the 4.043e-02 gap to 7.524e-03 and the residual is what says the closure is incomplete; on the same target with only the cx noise, the same three training circuits fall on a line to 1.110e-16 and the mitigated value is on the exact one to 1.665e-16, so the residual separates a premise that held from one that did not rather than being decorative. On h(0); ry(0, 0.6); cx(0, 1) observed as Z0 with two-qubit depolarizing noise at 0.06 on the cx and one-qubit depolarizing noise at 0.03 on the h, the two training points read ideal 0.0 and -1.0 against noisy -5.6e-17 and -0.936000001, so the fitted slope is the reciprocal of the shrinkage the model applied, 1.068376067, and the target's exact -0.564642473 is read as -0.528505356 unmitigated and recovered to 4.4e-16 mitigated -- a two-point fit, so that agreement is an arithmetic identity and the residual is reported as absent rather than as evidence. Demonstration scale: two-wire circuits on the CPU density-matrix path with at most three training points in these measurements. No performance, scaling, hardware or fault-tolerance claim follows from it, and no advantage over sampling the target directly is claimed.

### Readout-error mitigation over a declared classical confusion

Correct a measured distribution for the classical misassignment a NoiseModel's readout rules declare, by grouping those rules into disjoint blocks and applying each block's transpose inverse, with the amplification the correction costs and the negative mass it may carry reported beside the corrected vector.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.readout_mitigation`, `flagquantum.algorithms.plan_readout_mitigation`, `flagquantum.algorithms.run_readout_mitigation`, `flagquantum.algorithms.run_readout_mitigation_counts`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../examples/algorithms/readout_mitigation.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** Readout-error mitigation over a declared classical confusion, which is a linear inverse rather than a fit: the correction is exact exactly when the declared confusion is the device's confusion, and nothing here checks that. A readout error that is miscalibrated, that drifts between calibration and use, or that is correlated in a way the model does not carry survives the inversion untouched, so a corrected vector that lands on the ideal distribution is a statement about the model before it is a statement about a device. The declared index convention and the runtime's flat index convention differ: a calibration table is written with the true outcome as the row index, while flagquantum.noise.model.NoiseModel.apply_readout_probabilities applies that table transposed to a vector whose qubit 0 is the most significant bit, so the correcting operator is the transpose inverse inv(P.T) and not inv(P). The two agree on a symmetric confusion and differ on every asymmetric one -- by 0.14285714 in the maximum entry on ((0.9, 0.1), (0.2, 0.8)) -- which is why the relation is asserted directly rather than through agreement with a symmetric table. The corrected vector is not a distribution and is not forced to be one: the inverse of a stochastic matrix has negative entries whenever the confusion is invertible and is not a permutation, so negative_mass is the sum of the negative entries, total_variation is the L1 distance to the observed vector, and is_physical states which side of the simplex the result landed on rather than asserting that it must be inside. Nothing here refits, smooths, or projects onto the simplex, and no maximum-likelihood correction is offered. The amplification is the price of the correction and it is the whole map's induced 1-norm: for a map that is the tensor product of disjoint blocks that norm is exactly the product of the blocks' own, not the worst block's, so sampling_overhead composes multiplicatively and equals the worst block's only when there is one block. The standard error bound the result carries is that amplification over the square root of the shot count, which follows because the transpose inverse's infinity norm is the inverse's 1-norm. That bounds the corrected weight's standard error rather than the correction's error against the truth, and the exact per-component variance is the full covariance (diag(d) - d d^T) / N with d the device distribution, not the sum over outcomes of v squared times d times (1 - d) that a per-outcome reading gives: the missing (v^T d)^2 term was measured 40 per cent low on the two-qubit case this unit is tested on, 0.046274639 against 0.064321607. A readout rule naming several qubits is inverted as one block rather than as its marginals, because inverting the marginals inverts a different operator; the correlated table this unit is measured on does not factorize, its joint form read as a matrix having a second singular value of 8.144e-03 where a tensor product leaves rank one. A qubit named by two readout rules is refused rather than composed, because the forward path would apply the confusion twice and the inverse of a doubled confusion is neither correction; an uncovered qubit is left exactly where it was and is named as uncovered rather than given a guessed confusion. A block whose smallest singular value reaches the declared floor is refused rather than inverted, because the inverse's magnitude grows as the reciprocal of that singular value and the correction would report weights no shot count can support; the floor is the caller's and the default SINGULAR_VALUE_FLOOR of 1e-6 is matched to the decomposition tolerance probabilistic error cancellation uses, so a tighter floor refuses more. A correlated block wider than MAX_CORRELATED_BLOCK_QUBITS of 10 qubits is refused before its matrix is built, because inverting it needs a 2048 by 2048 float64 matrix and its singular values. An observed distribution whose rows fall further from one than NORMALIZATION_TOLERANCE of 1e-6 is refused, and one inside that tolerance is corrected rather than rescaled silently; a histogram whose keys are not all the plan's width, whose total is zero, or whose counts are negative or boolean is refused. The plan's identity is a digest of the confusion and the width and nothing else, and the corrected distribution is a classical vector rather than a quantum state, so nothing here restores positivity, enforces a rank, or reports an entanglement property.

### Gate and circuit folding by an exact identity

Lengthen a program by inserting each instruction's own inverse and then the instruction again, either distributed one instruction at a time or as whole repeated bodies, and report the length ratio the fold actually realized, the instructions it added, and the folded program.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.folding`, `flagquantum.algorithms.fold_program`, `flagquantum.algorithms.FoldingPlan`, `flagquantum.algorithms.FOLDING_STRATEGIES`
- **Runtime modes:** `local_statevector`, `density_matrix`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../examples/algorithms/folding.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** Gate and circuit folding, whose premise is about the device and whose output is a length ratio rather than a noise estimate. The fold is U (U-dagger U)^m, so it is an exact identity for every unitary the body is made of and the only deviation it contributes is the dtype's own rounding: measured on the five-instruction body h, cx, rz, ry, t the amplitude gap at complex128 is 1.6e-16 for both strategies, which is the floor of the state comparison rather than a number the fold added. That is what makes the method different from the three units beside it -- nothing is approximated and nothing is fitted -- and it is also what makes a channel in the body a refusal rather than something to skip: a noise channel has no unitary inverse, a fold that dropped it would change the ideal signal rather than only the noise, and the refusal names the instruction and the reason. The assumption the method does rest on is not visible in the program and is not checked by it: repeating an instruction has to repeat that instruction's error and change no other instruction's error, so crosstalk, drift between the unfolded and folded points, and a calibration that moved between them all violate the premise while leaving the program looking correct. What the unit returns is therefore a ratio and not a strength: the realized scale factor is a length ratio, the conversion from a length ratio to a noise strength belongs to the extrapolation the caller runs, and a caller who reads the ratio as a measured error strength has substituted the device's behaviour for the model's. The realized factor is the abscissa flagquantum.algorithms.run_zne fits against, not the requested one, because it is the ratio the noise saw; the plain scaling of that unit multiplies a channel parameter and is a different unit of scale, so a call naming both a fold and a scaling callable is refused rather than composed. The two strategies are not interchangeable. A circuit fold repeats whole bodies, so its realized ratio is 1 + 2m and a request between two odd integers overshoots: on the five-instruction body a request of 1.4 is met by 3.0 in fifteen instructions. A gate fold distributes the same pairs one instruction at a time and reaches a request exactly whenever the arithmetic allows: the same request of 1.4 is met exactly in seven instructions, and a request of 2.2 is met exactly in eleven where the circuit strategy's next reachable ratio, 3.0, costs it fifteen, so the exact factor is also the cheaper one. Because both strategies reach a ratio in steps of two instructions, distinct requests can realize one length: under a circuit fold of the five-instruction body the requests 1.4 and 2.6 both realize 3.0, and a run handed such a set is refused by naming the duplicated ratio rather than by failing inside the linear solve, because repeated abscissas make that system singular. A gate fold spends its pairs leftmost first, so its added gates land where the strategy puts them rather than where the caller's observable is sensitive, and a readout blind to a pair reads a flat curve over a program whose noise genuinely grew: on the five-instruction body with depolarizing at 0.03 the added pair lands on the leading h, and a zz(0, 1) readout reads 0.672956129888 at both ratio 1.0 and ratio 1.4 while xx(0, 1) reads 0.242863810368 and 0.223823288052. Four further refusals are deliberate and each names what it measured: a scale factor below one, which would have to remove instructions and change the ideal signal; a non-finite factor; an empty program, which has no instruction to fold; and a custom instruction whose matrix is not unitary or not square, because the fold repeats it with its own conjugate transpose and the identity would not hold. A program carrying a noise channel is refused before any of that, and the fold preserves the body's measurement and observable nodes as well as its instructions, so a fold of a program that declares them keeps them. This is a program transform, not an execution path: it builds a flagquantum.core.ir.CircuitIR and the existing runtime executes it, so no new target, runtime option, result field or execution mode is added, and no Stable Core export follows. Not here: any estimate of the noise a fold amplifies, any fold of a noisy program, any strategy beyond the two named, any fold count beyond the realized ratio, and any noise-model-aware placement of the added pairs. Demonstration scale: two- to five-instruction circuits on the CPU statevector and density-matrix paths, with folds up to a ratio of seven. No performance, scaling, hardware or fault-tolerance claim follows from it.

### Simultaneous perturbation stochastic approximation

Minimize a scalar objective with no gradient, from two objective evaluations per step whatever the parameter count, on a recursion whose direction is one randomly perturbed finite difference, and run a fixed step budget in one call to read the point, the cost at it, the trajectory and the evaluations spent.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.spsa`, `flagquantum.algorithms.SPSAOptimizer`, `flagquantum.algorithms.SPSAResult`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../examples/algorithms/spsa_optimizer.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** The estimate this optimizer builds is biased for every finite perturbation and is not a gradient: its expectation reaches the objective's gradient only as the perturbation shrinks, so a single estimate is not a descent direction and the update it produces is an approximation of a gradient step. An objective that has an exact gradient is served more cheaply and more accurately by autograd or parameter shift, and this unit says so in its own module docstring rather than presenting itself as a preferred optimizer. What it supports is a cost claim and not an accuracy claim: one step spends two objective evaluations whether the objective has one parameter or 128, measured at parameter counts 1, 2, 8, 32 and 128, where a parameter-shift gradient spends 2*n. The optimizer executes nothing itself -- it calls a callable the caller supplies and never inspects it, so no runtime mode is selected, no circuit is built, no observable is measured, and the caller's objective owns whatever execution it performs. The perturbation is drawn from a torch.Generator the caller passes, which makes a seeded run replay on the parameters' own device; without one an internal generator is created for the parameter device and the draw is then not reproducible from the call site. Parameter names are domain names rather than the published single letters: parameter_gain is a, perturbation is c, stability is A, parameter_gain_exponent is alpha and perturbation_exponent is gamma, with Spall's defaults 0.602 and 0.101. Averaging the estimates, a per-coordinate or blockwise perturbation scale, constraint handling, and resuming an optimizer from serialized state are all absent, and each is a second algorithm with its own convergence conditions rather than a knob on this one. No convergence rate, iteration bound or confidence interval is computed or reported: the numbers a run produces are a trajectory of one objective and the spread across seeds is the estimator's variance rather than a tolerance. The fixed-budget surface is minimize, which is the shape the simplex search beside this unit has, so one objective can be handed to both and compared; it differs from that unit's in what it returns. NelderMeadResult reports a best-so-far vertex together with the two spreads the run stopped on, while SPSAResult reports the *last* iterate and no spread at all, because a biased recursion of this kind has no comparison that would make one iterate better than another and its perturbation shrinks by construction, so a spread threshold would report a settled point as unsettled. There is therefore no converged flag here and none is missing: a caller reads the cost sequence or runs the deterministic unit. The two sequences are indexed by the optimizer's own step counter, so a second minimize on the same object continues the recursion rather than replaying it, and the counter is what makes an SPSAResult's evaluations field 3 * steps + 1 rather than a total; a run that has to be replayable is made by building a fresh optimizer with the same seed. It makes no performance, convergence, scalability or hardware claim, and it adds no root-level fq name.

### Nelder-Mead simplex search

Minimize a scalar objective with no derivative and no random draw, by reflecting, expanding, contracting and shrinking a simplex of n + 1 vertices until two measured spreads fall under the caller's thresholds.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.nelder_mead`
- **Runtime modes:** `not_applicable`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `not_applicable`
- **Start:** [quick example](../../examples/algorithms/nelder_mead_optimizer.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** This is a local method and its converged flag is not a statement about a minimum. A run stops when the objective values across the simplex fall under atol and the vertex positions across the simplex fall under tolerance, and a simplex can collapse onto a point that is neither a local nor a global minimum; the widely used variant this unit implements has no complete convergence theory in more than one dimension, which the returned result carries in its own limitations rather than leaving to this field. The failure is measured and not merely described: on the two-well quartic (x**2 - 1)**2 + 0.1x started at 0.5 the run reports converged=True on a value 0.199984362162 above the value it reaches from -0.5, and tightening the thresholds does not repair it because the simplex is inside one basin. There is no restart, no multi-start, no basin hopping and no simulated annealing, so the basin the starting simplex is placed in is the only one a run can reach, which is why initial_simplex is public and why the (n + 1, n) simplex is the caller's to build. The premise is a deterministic objective: every decision the method makes is a comparison of two objective values, so an objective whose value moves between two evaluations of the same point turns each decision into noise and the trajectory into a walk, and a stochastic objective is the subject of the spsa unit beside this one rather than something this unit tolerates. A starting simplex that does not span all n parameter directions is refused by name, which is deliberate and is also a boundary: the collinear construction the published counterexample uses cannot be expressed through this entry point, so the counterexample is refused rather than reproduced, and what remains reachable is a local minimum. The cost is a count of objective evaluations and not a latency, a device cost or a parallel schedule: vertices are evaluated one at a time, one evaluation per call, with no vectorization of the simplex, and the count is bracketed by (n + 1) + iterations at the lower end and (n + 1) + (n + 1) * iterations at the upper end rather than being a function of the parameter count alone. No derivative, curvature or uncertainty is estimated or reported, because the method reads only the order of objective values and two objectives with the same ordering produce the same trajectory. Bounds, constraint handling, feasibility and penalty notions are absent, so a constrained problem is only as well posed as the caller's own transformation of it. The optimizer executes nothing itself: it calls a callable the caller supplies and never inspects it, so no runtime mode is selected, no circuit is built and no observable is measured. The four coefficients, the initial step, both thresholds and the iteration budget are the caller's, no checkpoint or resume protocol exists, and the one arithmetic deviation the unit does make is that a simplex not carrying the parameters' own dtype is refused rather than silently promoted. It adds no root-level fq name and leaves the Stable Core surface untouched.

Accepted gates are exactly the thirteen Clifford opcodes in flagquantum.core.operator_schema -- i, x, y, z, h, s, sdg, sx, sxdg, cx, cy, cz, swap -- and every other opcode is refused with a CapabilityError naming it and the accepted set. ccx and cswap are refused because neither normalizes the Pauli group, so they are not Clifford gates despite being permutations; t, tdg, the rotation and controlled-rotation family, phase, u1, u2 and u3 are refused for the same reason. Circuits passed to sample_stabilizer must be noiseless: the four noise channels are refused rather than sampled as unitaries, so no readout error, depolarizing, damping or trajectory behavior is available. The second entry point, sample_noisy_measurements, is the exception, and it is not a widening of that refusal: it executes a channel at an explicit position a caller has already chosen, so the frame attribution is the caller's placement and not an inference the engine makes. What it accepts is the class its operators define -- a mixture of Pauli unitaries up to a global phase, on as many wires as the channel acts on -- and a channel outside that class is still refused by name, so a general damping channel, a thermal relaxation channel, and a coherent over-rotation remain refused rather than approximated. The engine names no channel instruction past two wires, so a wider frame is spelled as a chain of correlated-error instructions, one term per non-identity frame; a chain term is conditional on no earlier term having fired, so each weight is divided by the probability the frames before it did not fire, and a distribution whose non-identity frames carry more than all of the probability is refused because the identity could not otherwise be the remainder. The third entry point, survey_stabilizer_program, reports that same classification without executing anything: it counts gates, resets, recorded measurements and noise instructions, reports whether every channel in the program is a mixture of Pauli frames, and collects one blocker per instruction the sampling route would refuse, naming the instruction index and opcode. It reads the IR and never imports the engine, so it answers without the optional distribution, and it is a census rather than a promise: an empty blocker list says every instruction translated, not that the samples are correct. Neither entry point reads a lowered measurement node or returns detection events or observable flips, so a detector error model is read through `flagquantum.qec.sample_memory_circuit` rather than off a run; decoding, error-corrected logical operations and hardware-backed sampling are absent. Only computational-basis outcome sampling and exact Pauli expectations of a noiseless program are supported, and a noisy program is sampling-only: a frame draw answers outcomes rather than one Pauli, so an exact value is refused by name. The routed mode does reach the engine for a noisy program. It lowers a scene-level `NoiseModel` into positioned channel instructions the way the density-matrix route does, admits the program when the engine's own survey reports that every instruction translates, and refuses it while planning -- before a plan is published -- when a channel is not a mixture of Pauli frames or a gate is outside the Clifford set. Sampling is not differentiable and returns no gradients. The execution route is explicit: `fq.ExecutionOptions(mode='stabilizer')` reaches the engine through `fq.run`, the planner publishes a plan whose `state_mode` is `stabilizer` and whose `state_bytes` is the packed tableau rather than an amplitude count, and the result reports `execution_path='local_stabilizer'`. Automatic selection never chooses this mode, so no existing plan changes meaning. Planning refuses a non-Clifford gate, a batch, a non-CPU device, a gradient request, a target that asks for a state or an amplitude, a sharded world size and a program without shots, and a noisy program the engine's survey cannot frame; sampling refuses a lowered request it cannot reconcile with its own arguments and postselection, and a memory limit below the tableau. None of those refusals is a fallback, and none of them is a scalability claim. Runs are CPU-only single-device work with no GPU or distributed sharding. A seed reproduces a run on one engine version and one machine instruction set; it does not pin a bit pattern across machines or engine versions. The capacity statement is representational -- memory grows with the wire count squared rather than exponentially -- and no throughput, latency or scaling claim is made.

### Variational solvers over a checked cost operator

Fit QAOA angles to a weighted MaxCut graph through one checked edge list that reaches both the cost layer and the operator the energy is scored against, build the MaxCut cost operator itself, and expose that same objective as a plain callable of the angle vector so a gradient-free optimizer can be handed it, with the uniform superposition's stationary point and the finite-layer approximation carried on the result.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.variational`, `flagquantum.algorithms.maxcut_hamiltonian`, `flagquantum.algorithms.run_qaoa`, `flagquantum.algorithms.maxcut_objective`, `flagquantum.algorithms.QAOAResult`, `flagquantum.algorithms.QAOA_ASSUMPTIONS`, `flagquantum.algorithms.QAOA_LIMITATIONS`
- **Runtime modes:** `local_statevector`
- **Hardware:** `cpu`
- **Gradient support:** `exact`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../examples/algorithms/variational_solvers.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** A solver family over one ansatz, and not a new simulator, a new cost model, or a sampled execution path. What run_qaoa adds to the primitives beside it is agreement: a QAOA circuit is built from a list of weighted ZZ edges while an energy is an expectation against some Hamiltonian, and nothing inside either one relates the two, so a caller can build the ansatz for one graph and score it against another and every number that comes back is then a number about a problem nobody posed. The edge list is checked once and reaches the circuit and the operator through the same tuple, which removes that freedom for this entry point and only for it: a caller who assembles qaoa_circuit and qaoa_loss themselves still has it, and nothing warns them. The operator is sum over edges of w_ij Z_i Z_j with no constant term, so its value on a computational basis state is the edge total less twice the cut and its minimum is W - 2 * (largest weighted cut); the QUBO route through max_cut_qubo and qubo_to_ising describes the same minimizers but is an affine image of it -- the constant changes no angle while the halving of every coefficient does -- so the operator here is the one whose coefficients the cost layer rotates by, and reusing the QUBO form for an angle sweep would search a rescaled landscape. A negative weight inverts that one edge's preference and is allowed; a self-loop is refused because Z on one qubit squares to the identity and the edge is then a constant shift rather than a cut; and a repeated undirected pair is refused rather than summed, because summing would count the edge twice in the objective while the cost layer rotated twice as well and the two errors would reinforce. The premise the method cannot check is where the start is: the first layer's cost and mixer both act on the uniform superposition, which is an eigenstate of every ZZ and every X, so the measured gradient at a zero start is exactly 0.0 for every parameter at every layer count -- measured on a triangle and a five-edge four-node graph, one gradient entry per parameter -- and a zero start therefore returns the zero start with the objective unchanged. The start is consequently a required argument and this unit does not perturb it, because a default displacement chosen here would be a claim about the caller's instance rather than a property of QAOA. A finite layer count is an approximation and not an exact solver: on the five-edge four-node graph at a constant start of 0.1, one layer reaches -1.4735270738601685, two layers -1.914364218711853 and three layers -2.9724555015563965 against an optimum of -3.0, so a larger layer count is not guaranteed to be closer in general even though it is here, and the energy is an expectation rather than a bound. The trajectory the result carries is a record and not a descent: Adam, the default, takes a step of the learning rate's size regardless of how flat the objective is, so history can rise, and only the final value is the result. Angles, the circuit and the objective are float32 because the circuit builder casts every angle to float32, so a float64 start is downcast rather than refused and the reported energy is float32-accurate. The update inside run_qaoa is autograd-based and its optimizer_factory is a torch.optim optimizer, so the gradient-free units this package ships -- SPSAOptimizer and NelderMeadOptimizer -- cannot be supplied in that slot: an SPSA step is a rate-limited update from two objective values rather than a torch.optim optimizer, and a simplex is a whole run released at once rather than one either, so one parameter could not carry both shapes without a dispatch hiding which method ran. The route is the objective instead. maxcut_objective returns the very callable run_qaoa minimizes, checked through the same edge list and split the same way, and it is readable with float() without a backward pass, so either gradient-free unit can be handed it; measured on the one-layer triangle from a flat 0.05 start, Adam reaches -0.9999997615814209 in 300 steps, SPSA -0.9999911189079285 in 400 steps at 1201 evaluations and Nelder-Mead -1.0000003576278687 in 706 evaluations at maxiter 200. Nelder-Mead reaches the optimum while reporting converged=False, because that flag measures the simplex collapsing and not the energy arriving, and SPSA reports no flag at all; what none of the three does is sample, so no route here carries shot noise and the route is not a shot-based or hardware execution path. The result carries the fitted angles and the energy at them and nothing about the cut: sampling the optimized circuit, decoding a bitstring, ranking sampled cuts and comparing a sampled best against the optimum are all the caller's steps, and no cut value is returned. Not here: a cost Hamiltonian for a general QUBO or Ising instance beyond the QUBO conversions flagquantum.algorithms.qubo already carries, any constraint, penalty or slack term, a warm start from a classical heuristic, a multi-start or basin-hopping wrapper, and a shots or hardware path. The VQE entry points are deliberately not part of this entry: they have their own registered capability, algorithms_vqe_solvers, because their premise and their reading of converged are not this unit's. Demonstration scale: weighted MaxCut instances of three to five edges on three to four qubits, fitted on the CPU statevector path for one hundred steps. No performance, scaling, hardware or fault-tolerance claim follows from it.

- **Documentation:** [guide](../../flagquantum/algorithms/README.md)
- **Known boundary:** A solver family over one caller-supplied ansatz, and not a simulator, a cost model, a sampled execution path, or an accuracy claim. Every energy here is an exact statevector expectation: nothing samples, so no route carries shot noise and none is a hardware path. The premise this family cannot check is the reference state the operator pool acts on, and it is the premise ADAPT-VQE's screen rests on. Screening appends a candidate at angle zero and differentiates the objective at that angle, which is exact rather than estimated, so a reference state that is an eigenstate of every pool generator screens every direction to exactly zero. Measured on two qubits against the transverse-field operator ZZ - X0 - X1, whose ground energy is -2.2360679774997898: the pool (ry, rz, rx) on wire 0 from the |00> state selects pool index 0 at a screened gradient of -1.0 and descends to -1.4142135623730354, while the same pool from the |++> state selects nothing, takes no adapt iteration, reports converged=True and returns -2.0. The loop cannot tell a direction that does not help at this reference state from one that would help at another, and nothing reports the distinction. converged reports why the loop stopped and not how close the energy came, which is the same reading NelderMeadOptimizer's flag is documented with. Measured on the same instance: a pool of one with a zero tolerance reports True at -1.4142135623730354, a tolerance of 1e-1 reports True at -1.4142135623730951, and a run limited to one adapt iteration of one optimization step reports False at 0.999999999, so the run reporting the exit is the one closest to the ground energy and the flag is an exit test in neither direction. The objective is the caller's circuit builder, and nothing checks that the builder applies every operator the pool selected or that it reads every coordinate it was handed. What is checked is the one case torch reports unhelpfully. A descent needs an objective that depends on what it updates, and torch raises RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn, which names neither the run nor the cause, so both entry points check first and name both: run_vqe with a builder that ignores its parameters raises ValueError beginning run_vqe: the objective carries no gradient, and run_adapt_vqe with a pool element that adds no dependence at the appended angle raises the same through run_adapt_vqe. A builder that reads only some of its coordinates is not caught, because the objective does carry a gradient then: an adapt run whose builder applies only its first selected operator selects and optimizes normally. run_vqe's returned energy is a fresh evaluation of the returned parameters and not the last history entry, and the two are different measurements: history records the objective at the start of each step, so on this instance a fifty-step run reports -2.2241294384002686 while the smallest value history held is about -2.2308, because the final Adam step moved the objective up. The result is where the run stopped, not the best point it visited, and no entry point keeps a best-so-far. Angles and energies are float32: run_vqe casts a float64 start down rather than refusing it, and a six-hundred-step run on this instance reaches -2.2360680103302002, which is 3.3e-08 below the operator's own double-precision ground energy, so a reported energy is float32-accurate and not a bound. run_layerwise_vqe is a sequence of fresh descents rather than one warm-started descent: each depth pads the new coordinates with zeros and re-runs the same objective from the previous stage's parameters, so a deeper stage starts where the last one finished rather than from an unrelated point, and the result carries one record per depth rather than one trajectory. A deeper stage can therefore report a higher energy than a shallower one on a general instance, and this unit makes no monotonicity claim. run_hybrid_vqe's stages are the optimization module's, so the methods available are that module's gradient-based ones and no gradient-free optimizer can be handed a stage even though the package ships two. Not here: the baseline's shape, which is a solver object whose ansatz and optimizer are configuration rather than a circuit builder and an explicit call, and a pluggable ansatz registry with it; a cost Hamiltonian for a general QUBO or Ising instance beyond the QUBO conversions the algorithms package already carries; any constraint, penalty or slack term; adaptive and multi-angle QAOA variants; a warm start from a classical heuristic; the constrained derivative-free method COBYLA gives the baseline's VQE path; a chemistry front end, since the operator is a Pauli sum a caller writes and no basis set, molecular integral or active-space selection is involved; and any shots, hardware, accelerator or distributed path. Demonstration scale: two-qubit model operators with circuits of two to eight parameters, optimized on the CPU statevector path for one hundred to six hundred steps. No performance, scaling, hardware, chemistry or fault-tolerance claim follows from it.

- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** A product formula and the exact circuit for one Pauli word, and nothing about accuracy. The circuit approximates exp(-i * t * H) and the approximation is exact only when the Hamiltonian's terms commute; otherwise the defect falls off with the step length at the composition's own rate, measured as a ratio of 2.007 at order 1 and 4.027 at order 2 per doubling of the step count on a three-wire transverse-field Ising Hamiltonian at t = 0.4, coupling 0.7 and field 0.5. No bound on that defect is computed or reported, because a bound needs a commutator norm the caller has to supply, and nothing here knows the caller's Hamiltonian; the module says so where the number would be. The exact side of every comparison the tests make is torch.matrix_exp of the dense generator, which exists at the sizes this repository simulates, so no rate here is a sampling result and no scaling claim follows. order is limited to 1 and 2: the higher-order Yoshida and Suzuki compositions spend more exponentials than they buy until a caller measures otherwise, and the module records that rather than offering them. order=1 is the Lie-Trotter product and order=2 the symmetric one, so a caller who asks for order 2 pays twice the exponentials and gets one order more of cancellation per step. A word whose support is only identity characters is refused for having no support, and the register-width check precedes it, so a zero-width register reports the width rather than the word. The word reader underneath the primitive is flagquantum.simulation.pauli's own, promoted from private for this unit, and it owns the character set, the length match against the target list, the target-uniqueness and non-negativity checks; this unit adds no second copy of any of them. The declared term order is preserved and never sorted, because a product formula's value depends on the declaration order and sorting would be a second, silent parameterization. There is no exp_pauli opcode: CUDA-Q applies exp(-i * theta * P) as one opaque instruction and decomposes it in its compiler, while this unit emits the decomposition -- a basis change, a CX ladder anchored on the word's first supported wire, and one rz at twice the angle -- which is what lets the static resource estimator count the gates, a router move them, and autograd reach a tensor coefficient through them. Measured on one term with a tensor coefficient at 0.6 and order 2: the readout is 0.715813373694 and its derivative is -0.161660517061. The ladder emits its inverse CX run in the same wire order rather than the reverse, which is valid only because every CX shares one target and its controls are distinct. This is a circuit constructor, not an execution path: it produces a Circuit and the existing runtime executes it, so no new target, runtime option, result field or execution mode is added, and no Stable Core export follows. Not here: error bounds, time-dependent Hamiltonians, qubitization as a public walk object, QSVT, and double factorization. The block encoding this unit sits beside has since been promoted out of svd.py into flagquantum/algorithms/primitives/block_encoding.py, which carries its own capability entry.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.primitives.block_encoding`, `flagquantum.algorithms.primitives.BlockEncoding`, `flagquantum.algorithms.primitives.WalkEncoding`, `flagquantum.algorithms.primitives.SpectralBlockEncoding`, `flagquantum.algorithms.primitives.spectral_block_encoding`, `flagquantum.algorithms.primitives.subnormalisation`

- **Start:** [quick example](../../examples/algorithms/block_encoding.py)
- **Documentation:** [guide](../../docs/guides/ALGORITHMS.md)
- **Known boundary:** A construction and a protocol, and nothing about cost, accuracy, or scale. The construction is the direct spectral reflection U = [[A, sqrt(I - A**2)], [sqrt(I - A**2), -A]] with A = H / alpha, emitted as one dense matrix on n + 1 qubits and built from torch.linalg.eigh of the input; the cost is therefore diagonalising the caller's matrix, and there is no gate-efficient synthesis, no block encoding of a matrix whose dimension is not a power of two, and no sparsity or structure the construction exploits. No error bound is reported, because the construction is exact for a matrix that is exactly Hermitian and an approximate H is the caller's error rather than one this unit estimates. One implementation ships (the spectral one) and one flag wire is used; two protocols are the surface consumers are written against rather than a built family, and a Pauli linear-combination encoding -- whose preparation is a superposition over coefficients rather than the identity, and which needs a multi-wire flag reflection -- is a second implementation behind the same two protocols and is recorded as its own capability rather than left implicit here. The matrix is detached onto the CPU before anything else happens, so no gradient flows from a circuit back to the entries that produced it: this is a classical precomputation over a matrix the caller has already formed, and the module says so rather than leaving it to be discovered. Two divergences from CUDA-Q are deliberate and stated: the flagged block here is +H / alpha, where CUDA-Q's qubitization folds the sign of H into the walk and carries -H / alpha in the block, and the flag ancilla and the operator's qubits are separate arguments here because FlagQuantum addresses qubits individually rather than through a combined register; neither changes what the walk step computes, and the walk identity is asserted for the block this unit emits. The step is asserted twice: as the equality of spectra that is its content, and as the matrix identity W = Z_ancilla U that is its definition, because a spectrum alone does not pin a step -- this construction's step is Hermitian, so it is its own adjoint and its own encoding is a Hermitian unitary on the same register, and only the composed matrix witnesses that the flip is emitted at all. Eleven refusals are deliberate and each is taken before any gate is appended, so a rejected call leaves an empty circuit rather than a half-built encoding: a non-tensor, a non-square, a non-power-of-two, a non-floating-point, a non-finite, a non-Hermitian matrix, the zero matrix, a factor below the spectral norm, a non-positive factor, a non-real factor, and a register that repeats a qubit, has the wrong width, or contains the flag wire. The eigendecomposition is dense double precision and the tolerance of 1e-6 covers the digits sqrt(1 - w**2) loses as w approaches one; a complex Hermitian matrix is accepted and its reflection is complex. The walk step is exposed as two protocol methods rather than as a public walk object holding a moment count, and QSVT and double factorization -- the algorithms the walk step exists to serve -- are absent. This is a circuit constructor: it appends to an ordinary Circuit and adds no target, runtime option, result field, or execution mode, makes no performance, capacity, convergence, or hardware claim, and no Stable Core export follows from this entry.

### Fermionic operator algebra and its fermion-to-qubit images

Build and combine second-quantised fermionic operators with the canonical anticommutation relations applied at construction, and map a Hermitian operator to the Pauli Observable the existing execution path already measures, through either of two fermion-to-qubit encodings.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.observables.fermion`, `flagquantum.observables.fermion.FermionOperator`, `flagquantum.observables.fermion.FermionTerm`, `flagquantum.observables.fermion.create`, `flagquantum.observables.fermion.annihilate`, `flagquantum.observables.fermion.number`, `flagquantum.observables.fermion.jordan_wigner`, `flagquantum.observables.fermion.parity_encoding`
- **Runtime modes:** `local_statevector`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../flagquantum/observables/README.md)
- **Documentation:** [guide](../../flagquantum/observables/README.md)
- **Known boundary:** A symbolic algebra and two transforms, and nothing that executes on its own. Two fermion-to-qubit transforms ship, Jordan-Wigner and the parity encoding, and they are the same operator written in two qubit bases: the parity image is the Jordan-Wigner image conjugated by the change of basis that replaces each mode's occupation with the parity of the modes up to it, which is measured rather than asserted, so a consumer written against Observable reads either one without being told which it holds. What the second basis buys is locality of the occupied-parity information and not a smaller image. Jordan-Wigner runs a Z string over the modes strictly below a factor's mode, so the first mode is a single Pauli and the last spans every wire; the parity encoding runs an X string over the modes strictly above it, so the last mode is one X plus one Z on the mode below and the first spans every wire. The widest factor image therefore costs one wire per mode in both encodings, reached at opposite ends of the mode list, and the reduction in worst-case Pauli weight that motivates the Bravyi-Kitaev and ternary-tree encodings follows from neither; those two remain absent. Both transforms take the mode count as an argument rather than inferring it, so a caller who names fewer modes than the operator addresses is the caller's error and is refused rather than silently widened, and both refuse a non-Hermitian operator for the same reason. Operators are stored normal-ordered against the vacuum, so equality is structural and a Hermiticity test is exact rather than a tolerance; the consequence is that two operators equal as matrices but not as canonical sums compare unequal, which is the documented boundary rather than a bug. The image of a structurally Hermitian operator has real dyadic coefficients under either transform and the imaginary part is checked against a fail-closed bound of 1e-9 rather than a tuned threshold, so a coefficient outside it is reported instead of having its imaginary part dropped, and no input this algebra builds needs the bound. There is no matrix form of a fermionic operator: the only numerical value is the Pauli image, which exists at the sizes the statevector path simulates. There is no circuit-level exponential of a fermionic operator, no molecular Hamiltonian assembly, no integral handling, and no sparse or dense second-quantised Hamiltonian; expectation values, sampling, and gradients follow from the image and the existing Observable path rather than from this module, which therefore makes no claim of its own about any of them. Nothing here executes, allocates a device buffer, or reads a runtime option, so the runtime mode named is the path its image feeds rather than a mode this unit runs.

### Hartree-Fock and the molecular qubit Hamiltonian

Turn a molecular geometry into the second-quantized Hamiltonian a variational chemistry workload consumes: a restricted closed-shell Hartree-Fock solve, the atomic-to-molecular-orbital transform, an optional frozen core and active space, a Jordan-Wigner observable, and an exact S_z = 0 energy where the determinant space allows it.

- **Maturity:** Development evidence
- **Public API:** `flagquantum.algorithms.molecular`, `flagquantum.algorithms.molecular.create_molecular_hamiltonian`, `flagquantum.algorithms.molecular.restricted_hartree_fock`, `flagquantum.algorithms.molecular.molecular_orbital_integrals`, `flagquantum.algorithms.molecular.second_quantized_hamiltonian`, `flagquantum.algorithms.molecular.fold_frozen_core`, `flagquantum.algorithms.molecular.exact_ground_state_energy`, `flagquantum.algorithms.molecular.MolecularHamiltonian`, `flagquantum.algorithms.molecular.HartreeFockSolution`, `flagquantum.algorithms.molecular.MolecularHamiltonian.energy_offset`
- **Runtime modes:** `local_statevector`
- **Hardware:** `cpu`
- **Gradient support:** `not_applicable`
- **Distribution semantics:** `single_device_fast_path`
- **Start:** [quick example](../../flagquantum/algorithms/README.md)
- **Documentation:** [guide](../../flagquantum/algorithms/README.md)
- **Known boundary:** The driver covers what the integral engine underneath it covers, so the basis is STO-3G and the elements are H through Ne; there is no basis-set selection, no correlation-consistent basis, and no comparison with a value from one, because that would compare two different Hamiltonians. The Hartree-Fock solve is restricted and closed-shell, so it is a statement about a singlet and nothing else: a multiplicity other than one is refused rather than approximated by a solution of the wrong symmetry, and so is an odd electron count. It starts from the bare core Hamiltonian and converges to the fixed point nearest it, so the energy is stationary in the density and is not proven to be the lowest one; a second solution at a different energy is not searched for. It is undamped and needs a few tens of iterations at the standard geometries, and it fails closed with the largest density change it reached rather than returning an unconverged density. There is no point-group symmetry, no symmetry-adapted orbital, and no tapering of the qubit Hamiltonian, and no spin-orbit or relativistic correction. The frozen core is exact for the active space it defines and not an approximation of the full problem: the frozen orbitals are held doubly occupied, so the energy it gives is the energy of that reduced Hamiltonian. The exact energy is dense diagonalisation of the S_z = 0 sector, so it is available only at or below 1024 determinants and is None above that; a larger molecule still gets a Hamiltonian, an SCF energy, and a Hartree-Fock determinant, and what it does not get is an energy to compare an eigensolver against. That value is the active-space energy, where CUDA-Q's fci_energy comes from PySCF over the full space, so the two agree only when no orbital is frozen and no active space is chosen. Nothing here executes a circuit: the Hamiltonian is returned as an Observable and the energy is a number, and it is the caller who runs a variational ansatz on it.

- **Start:** [quick example](../../examples/remote/realtime_device_call.py)
- **Documentation:** [guide](../../flagquantum/remote/realtime/README.md)
- **Known boundary:** This is the software half of a realtime control surface and nothing else. It owns the 24-byte packed request and response headers, the ten payload type ids, the 12-byte type descriptor, the eight-argument and four-result limits, little-endian and IEEE-754 encoding, least-significant-bit-first bit packing, the function-id hash, the function table, the status convention, and the channel-selection seam. The type ids, the descriptor layout, and the argument and result limits are taken from CUDA-Q's published protocol so an interoperating implementation produces the same bytes, while the field names, the default slot size of 384 bytes, and every Python behaviour are FlagQuantum's own: CUDA-Q requires a slot size explicitly and documents no default, and a function-id miss raises a FlagQuantum exception here whereas the published dispatcher clears the slot with no response. Payloads are typeless on the wire, so a schema disagreement between a caller and a handler is caught out of band and not at runtime. LoopbackTransport is the contract fake and performs no I/O. A realtime call is consumed by a service-side handler; the simulator is not a sanctioned consumer, because architecture.toml forbids simulation from importing remote, and no realtime execution mode, runtime option, target, or result field is added anywhere. The parity rows for realtime_transport, realtime_feedback_loop, and realtime_sensor_bridge remain unsupported; only realtime_host_api moves to partial. No Stable Core export, capability availability claim, or maturity claim above development evidence follows from this entry.
