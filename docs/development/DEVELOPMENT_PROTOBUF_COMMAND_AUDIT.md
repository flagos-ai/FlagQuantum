# Complete protobuf generation command audit

## Full source and native ownership

Q-0041 is the complete `dev_tools/build-protos.sh` from Qualtran v0.7.0 commit
`bcb17bb25360ed68ce3bc084645db3e929799389`. Its Git blob and all eight input
schema blobs are verified in the focused acceptance tests.

`tools/development/protobuf_command.py` owns explicit developer code generation
and checking. The existing process helper owns the bounded child invocation.
The caller supplies the schema root, output root and schema paths. Framework
wire formats are owned by `flagquantum/compiler/formats`. Their existing private
runtime descriptors and typed encode/decode contracts supply the production
messages. This command supports generation of external schema artifacts for
source auditing and developer use. It adds no production dependency or schema.

```sh
python -m tools.development.protobuf_command \
  --schema-root /path/to/schema-checkout --output /path/to/generated \
  package/protos/first.proto package/protos/second.proto
python -m tools.development.protobuf_command \
  --schema-root /path/to/schema-checkout --output /path/to/generated --check \
  package/protos/first.proto package/protos/second.proto
```

Successful generation and an unchanged check exit zero. Drift exits one.
Invalid command arguments exit two. Compiler failure returns its exact status.
The explicit paths replace the source's fixed `qualtran/protos` and repository
output paths. This supports maintenance of the existing `circuit.append(op)`
workflow through its owned wire-format tooling.

## Checks, writes and explicit source corrections

The source scans new `*_pb2.py*` files and Git-tracked old files. The native
output scope is the explicitly supplied directory and the two generated file
extensions `.py` and `.pyi`. It checks all outputs in that scope, including
untracked files, and excludes bytecode and editor backups. This is an explicit
scope adaptation from the source's whole-checkout tracked-file inventory.

The native check compares names and complete bytes. It reports all missing,
extra or differing artifacts in sorted order. Checks leave existing files
untouched. Apply copies generated artifacts in sorted order, preserving equal
files' modification times. It retains stale outputs as the original apply mode
does. The next check reports those stale outputs for explicit removal.

Both modes compile in a temporary staging directory before any apply writes.
Compiler failure and timeout leave the output directory unchanged. Staging is
cleaned on success, drift, child failure and exception. Changed artifacts are
copied to a temporary file on the destination filesystem and individually
replaced atomically. A filesystem failure during apply can leave earlier complete
files updated. The command provides per-file atomicity, and retries regenerate
the full set and skip files already equal. It does not promise a multi-file
transaction. File modes and bytes come from the generated artifacts.

The source directly writes production output in apply mode and retains failed
check directories. These lifecycle corrections are explicit. Child execution has
a 1200-second timeout, replacing the source's unbounded compiler call.

The original check calls Bash `mapfile`. On the tested macOS Bash 3.2 this command
is absent. Both array loads print errors, comparison sees empty arrays and the
script reports success even for changed, missing and extra files. The original
false success is executed and retained. A test-only shell input-reader shim
supplies the unavailable array primitive so the unchanged source's remaining
comparison and cleanup branches can be exercised. It is not a source patch or
a claim of execution on another Bash version. Source and native compiler-failure
statuses are checked separately. A first shim used unsupported Bash 3.2 array
assignment through `printf -v`; the harness was corrected to shell-quote values
before assigning them with `eval`. All final tests use that corrected shim.

They are installed solely in `ftqc-reference-env/protobuf-build-deps`. Tests
check the two installed distributions against the original lock. The previously


notices. Metadata/license hashes are recorded in

by another compatible generator environment without changing production format
consumers. The original development lock parent remains independently open.
