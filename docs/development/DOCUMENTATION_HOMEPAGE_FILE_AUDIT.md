contents are generated by `tools.development.notebook_publication`. The existing
documented generation stage precedes Sphinx rendering. Documentation commands
now consistently include that stage, so a renderer is not presented as creating
missing content. Generated notebook copies retain their existing output policy.

## Verification and boundaries

The actual native root and its complete generated catalog render together in a
1,633-document site. All 120 authored notebook copies preserve their bytes, have
HTML outputs and are reachable through the actual Sphinx toctree from the root.
The root links to fundamentals, the library, curated API, contracts and Stable
API inventory all resolve. Both authored root/library entries have zero warnings.
All six existing site/configuration/renderer/example tests pass. No new test
merely mirrors documentation prose, and notebook execution stays disabled.

The Bell example is evaluated locally with the full absolute complex state
`[0.7071067690849304+0j, 0j, 0j, 0.7071067690849304+0j]`. Its public `to_ir()`
contains the existing two emitted instructions. The homepage declares no separate
cost model or work registers. The first evidence script incorrectly tried to
read `Circuit.instructions`; it was corrected to the existing public `to_ir()`
view and the unchanged completed render was inspected again. No product code or
reference source changed for that harness correction.

The initial full build reports 2,218 retained content warnings; the final
incremental build reports 1,499 warnings from its smaller processed scope.
Those counts are not evidence of a whole-site warning reduction. Existing
orphan pages, cross-root repository links, optional lexers and missing referenced
images remain visible. Root/library routes and all catalog pages are verified
independently of those warnings. Source/model or notebook-owner acceptance is
not inferred from a successful page build.

Whole-tree content warnings, the static API generator's inherited-setter refusal,
source MBUC/Autodoc discrepancies, scientific dependency locks and hosted
ReadTheDocs configuration remain separate open scope. No new source-defect waiver
or API approval is introduced. This is a documentation/navigation batch, with no
primitive emitter, model formula, numerical kernel, measurement protocol or
workspace ownership change. No fresh scientific notebook, install, hardware or
package-publication evidence is claimed.
