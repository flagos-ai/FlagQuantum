# Internal forwarder retirement

Baseline: `5f8e97c771925ebaf0a19f8fca26ab16c328ec4a`. Audited #1084 head: `9b1a8cd196f9d8b8427b382c404f66705cc57840`.

283 tracked files are removed, including 138 root tool command wrappers. 100 current public compatibility entries (the initial 99 plus one proven public-plan serialization locator) and 3 #1084-dependent internal files are explicitly retained below. The latter are not public promises.

## Completed removal

- Old Kernel, JAX, algebra and private Torch frontend directory trees are removed; the old structured frontend keeps only the two incoming #1084 test dependencies and their import parent.
- Internal Runtime helpers, service helpers, deployment helpers, provider helpers, root model alias and compiler module/training facades are removed. All existing callers use their authoritative owners.
- CI, local hooks, wheel test commands, tools, notebooks/scripts, docs and tests use canonical tool commands. The standalone pre-checkout source bootstrap and four #1084-modified root tool implementations remain real implementations, not wrappers.
- Generic module alias injection and its helper are deleted. Canonical imports do not synthesize retired modules. Public facades share exported classes/functions through ordinary imports.
- Credential classes remain public at their supported namespace exports, but explicitly reject pickle. Their private historical credential modules are removed; they are not justified as serialization compatibility.
- Runtime imports the same three approved frontend symbols directly from their authoritative Torch frontend modules. Exact importer/name restrictions remain in architecture policy; there is no intermediate compiler facade.
- The source ledger keeps historical evidence identifiers without requiring historical files to exist. Missing targets, reintroduced files and operational imports of retired modules fail checks. Frozen contracts and raw evidence are unchanged.
