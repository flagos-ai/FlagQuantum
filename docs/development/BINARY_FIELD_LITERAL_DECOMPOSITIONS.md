# Binary field source decomposition boundaries

This G2 implementation contract follows the already authorized full-file
migration and faithful-source closure rule. No Stable Core export, opcode,
serialized vocabulary, metadata validator or numerical arithmetic admission is
changed. Original Qualtran v0.7.0 files remain unchanged.

Compiler owns literal decomposition graphs. Square retains the original M/R
matrix-power schedule and the original ignored physical inverse flag. Existing
mathematical Frobenius and exact inverse owners keep their behavior. Both word
profiles share the same coefficient-array/word adapter and binary PLU emitter.

Register addition retains the source's loop over field degree, which is distinct
from storage width for an odd-characteristic field. Such a graph is a raw-bit
unitary and can leave the field's valid value domain. It must not be presented
as numerical nonbinary field addition. The existing mathematical binary adder
continues to reject odd-characteristic fields. Source scalar field callbacks
remain separately owned by Simulation.

Simulation owns explicit realization of numerical field declarations as quantum
storage. The existing register_type projection remains fully literal, including
scalar objects, symbolic expressions and classification order. A separate
resolve_quantum_field_storage step converts concrete integral aliases to the
existing Python-integer IR vocabulary and applies the existing Core storage checks.
The lazy encoding and original descriptor remain unchanged. Classical projection
and classical storage realization are unchanged. Explicit malformed or boolean-valued Core
field descriptors remain rejected by the unchanged Core validator; projection
does not admit a new IR parameter kind, rounding or an unresolved dimension.

Examples compose these owners for the existing catalog entry points. Concrete
integral constant values are lowered to bit patterns without numerical rounding;
symbolic constants preserve the original decomposition refusal and symbolic
resource bound. Actual source byte/codecs, primitive inventories, independent
models, numerical callback results and corrected native operations are separate
observations. Ordinary use remains circuit.append(op).

Implementation commits are separated by domain/module. Acceptance requires
actual untouched-source calls, operands and returned leases; full complex
operators and coherent spectators; zero clean work; and independently queried
source model counts. No measurements occur in these linear fixtures. Existing
source tests, notebooks and presentation evidence are reused after checking that
the selected dependency paths are unchanged. Source defects do not waive a
missing valid-source native path.


## Karatsuba literal dependency profile

Compiler may compose a separately named literal Karatsuba implementation and
RIGHT-result shell using the existing polynomial, shift and constant owners.
The original generic constant adjoint reverses its logical child direction,
but the resulting linear physical builder still emits forward PLU. The literal
physical profile must therefore use forward constant scaling at that location.
The established mathematical Karatsuba owner keeps exact inverse scaling.
Both profiles share one root schedule and allocation shell; do not duplicate the
recursive polynomial algorithm or claim literal output is a mathematical product.

The implementation has three MSB-first THRU words f/g/h. Its h is arbitrary
logical data, not clean work. The public source shell has THRU x/y and RIGHT
result, initially allocated zero. Recursive high padding is private clean work
and must be verified zero. Frozen source degree-one public refusal is retained.
Before this closes Q-0519, qualify actual catalog calls and logical adjoint
identities, validate raw source operators/aliases and independent resource models,
and retain measured-erasure compatibility or failure as a separate observation.
No public API, IR vocabulary or numerical execution contract changes here.


## Zero-pivot PLU and literal shifts

The existing private Core `BinaryMatrix.plu` contract is unchanged: singular
matrices return None. A separately named private matrix method may retain the
same first-pivot factorization with missing-pivot columns, sharing one internal
factorization loop. Its consumer is static Compiler decomposition, not state
execution. No Stable Core export, IR, parameter validator or serialized schema
changes. Compiler shares the existing PLU gate schedule for both profiles.

A literal shaped-bit Program accepts the source's square binary matrices,
including zero/rank-deficient cases, and ignores the source physical inverse
flag. It must preserve distinct declared forward/adjoint function identities
when used by graph consumers. The mathematical linear Program remains invertible
only. The original declaration may be negative for missing diagonals; retain it
as a source model observation, separate from nonnegative measured primitives.
Never describe the emitted reversible circuit as implementing a singular matrix.

Binary field constant decomposition may use this literal child for zero as well
as fitting nonzero constants. The mathematical constant owner remains nonzero
only. Source left/right shift constructors receive a signed iteration count;
negative counts emit no loop, rather than a mathematical opposite shift. A
separate literal shift entry preserves that behavior using the existing no-shift
word views. Numerical callbacks remain separately owned by Simulation.


## Raw nonbinary physical consumers

Existing approved raw field storage may flow through literal decomposition
profiles without admitting numerical nonbinary quantum arithmetic. Compiler
accepts a concrete raw field word using existing Core validation. Numerical
constant matrices stay in Simulation; a typed constant-matrix wrapper only
adapts its provided binary coefficient matrix and declared direction.

The literal monomial owner interprets the provided integer polynomial in its
metadata characteristic, retaining source nonzero degrees and the distinction
between field degree and raw bit width. It shares the existing shift loop.
For degree one, the source omits its final coefficient reversal; retain the raw
bit reversal even for count zero. The mathematical binary shift stays unchanged.

The literal quadratic owner shares its entire schedule with the mathematical
binary owner, injecting literal left/right shift children and looping over raw
word width. Its RIGHT output is caller data; its exact LEFT inverse releases
only a matching computed value. No private quantum work or measurements arise.
Degree-one inverse allocates a same-type RIGHT word and calls the existing
literal degree-prefix addition, with no junk port. Source numerical callbacks
remain separate, including their disagreement with these raw circuits.

Examples own actual catalog selection and numerical matrix construction. Static
Compiler transforms import no source SDK or numerical field library. Retain
source nonbinary Karatsuba and higher inverse decomposition failures. No public
API, IR, Core storage or numerical arithmetic admission changes are authorized
or needed for these internal consumers.


## Declared inverse identity and complete caller qualification

Literal square and constant inverse calls retain distinct existing named
function definitions even when their primitive recipes coincide. Typed word
composition binds each child's actual entry. Mathematical components continue
using their exact inverse definitions. No scalar no-op, block-label tag or new
Core metadata is introduced.

The product catalog selects literal Karatsuba. Examples may qualify a constant /
linear direction only from a complete match of the owning literal product
schedule: the first constant child is declared inverse, the second forward, and
each has one linear child. Treat generated names as opaque IDs. Do not infer a
source direction from a function-name suffix or equivalent primitive body.
Incorrect bodies, ambiguous sharing or an unmatched owning schedule do not gain
a source label. Existing mathematical inverse catalog graphs keep their explicit
separate scope until the full inverse owner is closed.


## Measured root dispatch and declared shift classes

The existing product-erasure Program may receive an explicit binary modulus when
its otherwise concrete field descriptor omits a polynomial. Keep the descriptor
and signature unchanged, validate the supplied polynomial and preserve all
existing explicit-polynomial refusals. Numerical default resolution stays in
Examples/Simulation. Compiler owns only the static provided polynomial.

The existing FieldProduct example's Karatsuba adjoint flag dispatches to measured
product erasure, consumes the owned result and retires its physical wires. Normal
append reserves private classical scratch after the caller's existing storage
using the existing scratch binder. It must not overwrite caller snapshots or
change Circuit.compose semantics. Through Karatsuba remains unsupported.

If literal left/right shift definitions have identical bodies, quadratic
composition retains distinct existing named entries for those declared classes.
Internal word calls bind the child's actual entry. Examples qualify their labels
only from a complete matching quadratic caller and its ordered shift calls.
Standalone mathematical operations and public Core defaults remain unchanged.
